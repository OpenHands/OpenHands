Search saved history.
Keep live chat connected.

An explicit, bounded reader for earlier conversation turns and displayed tool output. Search results open their own small context window; the live event store stays mounted.

The behavior change

01 · Scan honestly

Partial is a visible state

Each explicit batch reads at most five pages. Progress reports examined events and matches. Continue scans older pages; Cancel discards a late in-flight result. Network failure, repeated cursors and an incomplete count comparison surface errors.

At 200 matches the user must narrow the query. A legacy timestamp-only backend needs a separate count to prove exhaustion.

HistorySearchSession.scanBatch

02 · Open bounded context

Replay pages, mount at most 24 events

The match retains its scan page anchor. Context replays that page and, only near a boundary, adjacent pages: at most three reads of 100 events. Only 24 neighboring events are retained for display, deduplicated and ordered. The matching event and its related tool call are expanded, using plain text without chat action buttons.

If the target cannot be recovered in this bound, the dialog reports a context error. Return to live closes it and restores trigger focus.

Boundaries worth reviewing

Cancellation is cooperative. The published client has no transport AbortSignal for these reads. At most one pending page per cancelled search can finish; its result is discarded.

Completeness is relative to the scan start. Live events can arrive after the first descending page. The dialog says it searches saved history from when the scan starts; run another search to include newer events.

Scope is checked at both ends of every page read. A changed environment cannot publish a result into a new scope. Credentials do not enter cache keys. The component performs only history/count reads and never starts or resumes an agent.

Verification map

The tests cover unloaded turns, full tool output, visible assistant thoughts, ACP display data, page bounds, continuation, cancellation, duplicate cursors, incomplete histories, errors, keyboard context navigation and environment changes. The running-app evidence uses an actual Agent Server serving SDK-prepared persisted events; the seed is test history and involves no model inference.
