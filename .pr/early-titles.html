EARLY CONVERSATION TITLES · REVIEW GUIDE

Reveal one title while the sandbox starts

Canvas opens the conversation immediately, shows the same shimmering New Chat label in the sidebar and header, then reveals the app-generated title. The app server owns the generation state and deadline; the existing launch store owns only navigation aliases and optimistic timing.

★ The new Cloud opt-in is additive and defaults off on the backend. Deploy enterprise #1119 first. Local and legacy Cloud conversations keep their existing title behavior. Start with useConversationDisplayTitleState and the Cloud create payload.

API before → after

Cloud POST /api/v1/app-conversations gains generate_title_on_submit: true. Optional response metadata is title_generation: {status: pending | generated | fallback, title, deadline_at}. A missing field uses the legacy path. This is an app-server contract; no Agent Server endpoint or minimum version changes. Contract source.

During the shared deadline the UI shows New Chat. Success reveals the generated title; failure or timeout shows the first-message fallback. Manual renaming clears generation state and immediately updates both caches. Header and composer geometry remain the layout established by #19202.
