Feature · Agent Canvas

Render Mermaid diagrams inline in the conversation

Agents emit Mermaid (flowcharts, sequence, ER diagrams) as fenced code blocks, and users create .mmd/.mermaid files. Both used to show as raw source. This PR turns them into real diagrams in the chat stream and the Files tab, keeps the source one click away, and never breaks a message when a diagram is invalid.

1 What changed

★ One-time, lazy, and defensive. Mermaid is loaded through a dynamic import() only when a diagram is rendered (mermaid-renderer.ts:30), so a conversation with no Mermaid block downloads zero extra bytes. Its output is sanitized before it reaches the DOM and an invalid diagram falls back to its source.

Before

```mermaid
graph TD;
  A[User]-->B[Agent];
```

A ```mermaid block rendered through the ordinary code path: syntax-highlighted text with a copy button (code.tsx @ base).

After

A diagram card: SVG in the body, a footer naming the artifact with View source, Copy, and Download SVG. Same card for a .mmd file (mermaid-diagram.tsx:42).

ⓘ Invalid diagram → the raw source is shown with a short note; the message is untouched.

2 The render pipeline

Three small pieces, each with one job (all in mermaid-renderer.ts):

StepCallWhy
load onceloadMermaid() — :30memoized dynamic import; initialized once with securityLevel:"strict", htmlLabels:false
validatemermaid.parse() — :73reject invalid diagrams so the caller can show the source, instead of returning partial output
rendermermaid.render() — :74produce the SVG string
sanitizesanitizeMermaidSvg() — :55DOMPurify SVG profile; forbids script/foreignObject and on* handlers
⚠ The input is agent/model output. Richer modes (loose) are never used; the raw SVG never reaches dangerouslySetInnerHTML without the DOMPurify pass (mermaid-diagram.tsx:132).

4 Safety & bundle cost

Security posture

  • strict Mermaid mode + HTML labels off
  • DOMPurify SVG profile as a second pass
  • script, foreignObject, on* forbidden
  • invalid diagram → source fallback, never a crash

Bundle

npm run build:app emits vendor~mermaid.* as separate lazy chunks only for conversations that render a diagram. Mermaid is pinned to 11.17.2; dompurify is 3.4.14.
