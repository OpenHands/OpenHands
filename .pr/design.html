Spec BM-004 · Agent Canvas

Show the active backend's execution mode (local / Docker)

Issue #18099 · read-only display of a value the agent server already returns.

Canvas already reads the server's runtime boundary to pick a conversation workspace, but operators cannot see it. This PR surfaces that value as a badge next to the existing version badge in the Manage backends view. No new endpoint, field, or contract: the only new code reads a value the server already reports.

★ Compatibility note. The shipped agent server (v1.50.1) reports the boundary as conversation_runtime, not the execution_runtime named in the issue. The display reads either — preferring execution_runtime when present — and renders nothing when neither is reported, so old servers are unchanged. compatibility.minimumAgentServer is not raised.

ground: src/api/agent-server-compatibility.ts · src/components/features/backends/backend-execution-mode.tsx

02 · Data flow

serverGET /server_info → { version, conversation_runtime: "local" | "docker" }
hookuseBackendServerInfo(backend) — one TanStack Query key ["backend-version", host, apiKey] shared with the version badge; gated to kind === "local"
resolvegetBackendExecutionMode(info) → "local" | "docker" | null (single reader of both field names)
render<BackendExecutionMode> → localized chip, or null when the server reports no mode
