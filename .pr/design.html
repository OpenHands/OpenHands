Stacked on openhands/automation-draft-management-testing

Setup page owns draft testing

Creating an automation no longer opens an agent conversation first. The setup form holds the draft, and a conversation starts only after the user sends a prompt. Saving, testing, and reading a failure stay on that page: a draft bar, a test-runs view, toasts, and a logs dialog that scrolls.

1What changed

★ The form is usable before any conversation exists. startSetup stores a blank draft under PENDING_AUTOMATION_SETUP_ID and navigates to /automations/setup. It does not call createConversation. use-start-automation-setup.ts:31

Edit-existing still opens a conversation immediately and uses Test, Save, and Close. New-from-the-automations-page waits.

2Create flow

Pending setup id

PENDING_AUTOMATION_SETUP_ID ("pending-new-automation") is the draft key until a real conversation exists. The setup panel skips conversation tag updates for that sentinel. automation-setup-draft-store.ts:83

Route automations/setup is registered before automations/:automationId so the sentinel path is not parsed as an id.

Custom event source

Choosing Custom clears the source, focuses it, and checks “Register this as a custom webhook source”. A known source such as GitHub unchecks and hides that option.

3Draft bar and test runs

DraftStatusBar sits at the top of the form column, aligned with the prompt. The title and time stay on the left. View test runs and Test stay on the right. A validation error, such as a missing webhook, is a full-width line under that row so it does not wrap into the buttons. automation-setup-panel.tsx:607

  • Toolbar Test is small and secondary, and stays disabled until the saved request matches the form.
  • The bar’s Test is small and primary, at the far right. Clicking either Test opens the test-runs page and starts the test.
  • DraftRunsPage has a back button, a page-sized title, an empty state, and a normal primary Test. The first run row is not highlighted. Errors use the red banner. automation-setup-panel.tsx:735
  • The agent profile pill is to the left of the model pill.

4Feedback and logs

Setup status used to render as green or red text under Additional options. A statusMessage effect now sends success through toast.success and errors through displayErrorToast. The form no longer renders automation-setup-status. Validation text that already appears on the draft bar and the runs page is not copied to the bottom. automation-setup-panel.tsx:866

The logs dialog is the scroll container (max-h-[80vh] overflow-y-auto on run-logs-body), with the title sticky. The output pane no longer has its own overflow-auto, which had grown with the log text and been clipped by the viewport. run-logs-modal.tsx:269
