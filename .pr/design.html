Agent Canvas · feature · issue #18101

Show a run's trigger reason in the conversation list

Canvas already receives why a conversation started — Cloud stamps trigger: "automation", the local agent-server stamps automation tags — but only used it as a boolean. This change turns that existing field into a localized, presentational label on the conversation row, its hover preview, and the compact sidebar row's hover preview. No new endpoint, request field, or response field; no change to filtering, the automation-name facet, or the reserved-tag set.

1What changed, decision first

One new pure helper maps the existing AppConversation.trigger to a localized I18nKey, falling back to the automation tags the SDK workspace stamps on local rows, and returning null for absent or unrecognized values so the row renders exactly as today. Three call sites consume it: the card metadata chip row, the hover preview, and the compact sidebar row's hover preview (which renders through the same footer).

★ Presentational only, and additive. The helper is the single source of truth for the label; isAutomationConversation, the automation-name facet, the tag filters, and RESERVED_CONVERSATION_TAG_KEYS are untouched. conversation-panel-list-helpers.ts:254

2API before → after

The change adds one exported function and reuses the trigger union already declared in the app types. additive — no existing signature changes; isAutomationConversation only narrows its parameter to the fields it actually reads.

Before

// conversation-panel-list-helpers.ts
export function isAutomationConversation(
  conversation: AppConversation,
): boolean {
  if (conversation.trigger === "automation") return true;
  // …automation tags…
}

// ConversationTrigger (open-hands.types.ts)
type ConversationTrigger =
  | "resolver" | "gui" | "suggested_task"
  | "microagent_management" | "automation";

After

// conversation-panel-list-helpers.ts:254
export function getConversationTriggerLabel(
  conversation: Pick<AppConversation,
    "trigger" | "tags">,
): I18nKey | null {
  const trigger = conversation.trigger;
  if (trigger && Object.hasOwn(
      CONVERSATION_TRIGGER_LABELS, trigger))
    return CONVERSATION_TRIGGER_LABELS[trigger];
  if (isAutomationConversation(conversation))
    return I18nKey.CONVERSATION_PANEL$TRIGGER_AUTOMATION;
  return null;
}
ⓘ The map is typed Record<ConversationTrigger, I18nKey>, so a future trigger (e.g. standing_intent) is a compile error until it gets a label — exactly the acceptance criterion "add the enum member and its localized string, nothing else".

3Render path & call sites

  • conversation-card-footer.tsx:202 — renders the chip in the metadata row (only when triggerLabelKey is non-null).
  • conversation-card-preview.tsx:237 — renders the preview row under a localized "Trigger" heading.
  • conversation-card.tsx:263 — a non-null label forces the footer to render, so the chip is never silently dropped.
  • conversation-panel.tsx:926 — threads conversation.trigger into both sites.

A follow-up review finding: the collapsed sidebar renders its own CompactConversationRow, whose hover preview uses ConversationCardFooter directly, so it bypassed the two call sites above and dropped the label. Fixed by threading trigger into the compact row and deriving the label there with the same helper.

  • compact-conversation-row.tsx — derives the label from trigger/tags and passes it to the shared footer.
  • conversation-panel.tsx — forwards conversation.trigger into CompactConversationRow.
  • compact-conversation-row.test.tsx — covers the compact hover path (recognized trigger, automation-tag fallback, unknown trigger).

5Risk & follow-ups

No durable state, no secrets, no lifecycle. The label is read-only display derived at render time; it creates, forks, stops, and reroutes nothing. The one compatibility question — does Canvas now require a new Agent Server field? — is no: trigger is already on the payload Canvas receives, and unknown future values degrade to no chip.

⚠ The runtime half (reporting new reasons such as standing_intent and a stop reason) belongs to OpenHands/software-agent-sdk / OpenHands/automation. This PR is the Canvas-only slice and does not add a wire field.
