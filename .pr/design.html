AGENT CANVAS · DRAFT REVIEW AID

Custom webhook registrations, not an event log

The Events view is a manifest-admitted, owner/admin-gated management surface for listing and creating custom webhook registrations. It integrates with the existing automation service on both local and Cloud backends. It neither delivers events nor enables an event-triggered automation when the deployment reports only cron support.

★ The key boundary: manifest admission requires Events route, page, navigation and endpoint together; the existing 0.24.0 dependency does not declare them, so the route remains unavailable until a newer extensions artifact is published and pinned.

03 · The user sees registration state, not a delivery promise

AutomationEventsRoute delays requests until permissions resolve, rejects unauthorized deep links, and distinguishes loading, empty, transient error/retry, and explicitly unsupported states. Empty-state copy warns that external delivery requires a publicly reachable URL but does not block creating a registration. The form uses a generic HMAC-SHA256 hex signature and never echoes user-provided secrets.

⚠ The local capabilities response advertised triggerKinds: ["cron"] and eventSources: [] even though GET /webhooks returned 200. CRUD availability is not evidence of event delivery. A banner makes this limitation explicit.
