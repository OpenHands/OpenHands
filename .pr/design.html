Feature · issue 18430 · additive

Child conversations can pin a saved agent profile

launch_child_conversation accepts an optional agent_profile name or id. A valid profile launches the child through the existing agentProfileId / agent_profile_id path, so that profile’s model is the one that runs. An unknown or unreadable profile returns guidance and creates nothing. Omitting the field keeps today’s default settings path.

1Pin the child, or launch nothing

★ A selected profile never falls back to the parent’s agent_settings. Restricted secret_refs stay on the server-resolved profile path, which is what drops secrets outside the allow-list. child-conversation-launch.ts:257

5Resolver rejects before create

🟢 added resolveChildAgentProfile

Local reads go through AgentProfilesService and ProfilesService. Cloud reads go through the picked backend from pickCloudBackendForLaunch, because the parent conversation is usually still on the local backend.

Match order is id, then name (matchProfile:61). A local OpenHands profile whose llm_profile_ref is missing from local LLM profiles is invalid. On cloud, the same miss — or an LLM list that cannot be read — still resolves: model is null and modelNote says the model was not confirmed, because a local parent only sees the per-user LLM list and an organization-only profile would otherwise be rejected. An ACP profile uses acp_model and does not consult LLM profiles. Array.isArray(secret_refs) — including [] — sets secretRefsRestricted.

Cases the tests lock
  • Unknown name: guidance lists saved profiles, and getProfile is not called.
  • Agent-profile list throws: guidance names the read failure. Nothing is created.
  • Local LLM profile absent: guidance names the dangling ref. Nothing is created.
  • Cloud LLM profile absent or unreadable: the profile still resolves with model: null and a note. The launch sends agent_profile_id only.
  • Cloud unknown agent profile: no profile detail read and no LLM list.

6Both targets reuse the profile path

✏️ changed launchLocalChild / launchCloudChild

Before, launchLocalChild called createConversation with task, workspace, and parent id only (:244 on main). After, a resolved profile adds agentProfileId, agentProfileKind, and agentLlmProfileRef (:356). That is the same local start-request field buildStartConversationRequest already turns into agent_profile_id and uses to omit agent_settings.

Cloud adds agent_profile_id on the existing AppConversationStartRequest (:505). Resolution runs after the “no cloud backend” check and before createCloudAppConversation, so a bad selector does not open a start task and does not read settings.

With no selector, resolveChildAgentProfile is not called and the create payload stays the previous object. The result says profile_source: "inherited", agent_profile_id: null, model: null.

7What the agent is told

The tool description at launch-child-conversation-client-tool.ts:54 now includes:

  1. Omit agent_profile to keep the current default settings path.
  2. Pass a saved profile name or id to pin that profile’s model on local or cloud.
  3. A copyable local example (target, task, agent_profile: "fast") and a cloud example that inherits the default (repository, branch, no profile).
  4. The split from in-conversation sub-agents: those stay inside the parent and do not take agent_profile.
  5. On cloud, a saved profile whose model is not on the visible per-user LLM list still launches. The follow-up sets model to null and says the model was not confirmed.
ⓘ The public page openhands/usage/agent-canvas/conversations.mdx lives in OpenHands/docs, which this pull request does not modify. The agent-facing contract in this repository is the tool description above.

8Risk

ⓘ When the parent is local, cloud LLM-profile confirmation uses the per-user settings route, because the connected cloud backend is not the active org. An org-only LLM profile missing from that route still launches: the result sets model to null and model_note says the model was not confirmed. The start request carries agent_profile_id and omits agent_settings.

Secret filtering stays on the agent server: sending agent_profile_id is what makes secret_refs drop the other names. This change does not rebuild the secrets map in Canvas.
