Issue #18445 — completed conversation opens with an empty chat window

Reproduction through the real built Canvas bundle and the real agent-server session socket (ws://…/sockets/session/<id>). Only the cloud API responses are mocked to create the bug condition: GET /api/v1/app-conversations returns the completed conversation, GET /api/v1/conversation/<id>/events/search returns 500 (the failing initial tail load), and GET /api/conversations/<id>/events/count passes through to the live server and returns 200. Conversation has 3 seeded user turns on the server.
BEFORE (base main) — silently empty chat
socket resume cursor: after_seq=9 (count−1 → history skipped)
rendered user messages: 0
the failed tail search was swallowed into an empty page, so the socket resumed past the whole log
AFTER (PR head) — history replays
socket resume cursor: after_seq=-1 (replay from the start)
rendered user messages: 3
the failed tail load no longer seeds an empty page; the socket replays the log
A video of both runs, concatenated in order, is at .pr/18445-repro.webm. The standalone driver is .pr/repro-18445.mjs. Reproduce with: node .pr/repro-18445.mjs http://127.0.0.1:18300 <conversationId> /tmp/out after swapping the built bundle under build/ between the base and PR-head commits.
