How a number gets on a card

Four steps. Each page works on one of them.
StepWhat happensWhere it is declaredService today
1The plugin declares its metrics: the keys it reports, what each key counts, and how.automation.outcomes.keysopen PR type, semantics, grain are in #818. The other fields are new: manifest
2The plugin declares suggested cards: how to show a metric.automation.outcomes.suggested_cardsgap There is no card resource yet.
3At run time the plugin sends facts to the service.Plugin code. The run has $AUTOMATION_OUTCOME_URL and $AUTOMATION_OUTCOME_TOKEN.merged POST /v1/outcomes · open PR period, occurred_at, dedupe_key, dimensions
4The factory page reads the facts and draws the card.The card, plus the key's default aggregationmerged GET …/outcomes/aggregate
Step 3 is plugin code, not manifest. But the key from step 1 decides which fields step 3 must send. A total needs a period. An increment refuses one. So each example on these pages shows the manifest and the POST side by side.
02

Reading guide

How to read the pins and the labels on every page.

Panes

Each example has the same parts, left to right and top to bottom.

Card (dark, left)The card as the factory page shows it, drawn 1:1. Under it, the facts the card reads, when they help.
ManifestThe part of .plugin/plugin.json that sets the card up. Highlighted lines are the ones the example is about.
The plugin sendsThe request the plugin makes at run time. Present when the key's rules decide what the request holds.
The card readsThe request the card makes and the answer. Every answer marked checked came from running the request against the service code in PR #818.

Pins

A pin joins a line of the manifest to the part of the card it controls. The numbers mean the same on every page.

1The card title. It comes from the card, not from the metric.
2The value. The aggregation and the window decide it together.
3The hint line. It comes from the metric description.
4The link. The whole card becomes a link, and a chevron shows.
5No place on the card. It says where the number comes from.
a bLetters mark separate cards when one example has more than one card.

Labels

Two kinds of label sit at the top right of each example. One says if the manifest field is proposed. The other says if the service can do the work today.

new: manifestA manifest field proposed by these pages. The manifest schema does not have it today. It rejects fields it does not know.
mergedThe service does this work in OpenHands/automation main today.
open PRThe work is in an open pull request and not on main. The text after the label names the PR.
gapThe example needs it and no pull request provides it yet. The text after the colon says what is missing.
checkedThe answer shown was produced by running the request against the service code. Not a guess.
03

The manifest fields

Every field these pages use, and where it stands.

The registry in the service holds type, semantics and grain for each key and rejects any other field. Everything else is a proposal for the manifest, and it would reach the service only when the registry grows to hold it.

FieldOnSaysStatus
typekeynumber, string, boolean, datetime or jsonmerged new: manifest
semanticskeyincrement (every fact counts, the default) or total (one number per period, the latest report wins)open PR #818 new: manifest
grainkeyThe period of a total: hour, day, week or month. A total needs one. An increment refuses one.open PR #818 new: manifest
label descriptionkeyThe name in lists, and the hint line on a cardgap: registry new: manifest
unit directionkeyHow to format the value, and whether up is good, down is good, or neithergap: registry new: manifest
aggregationkey, cardHow the facts in the window become one number. The key names a default. A card can set its own.merged sum count avg min max count_true count_false · gap last rate
windowcardThe span the card reads: all, 7d, 30d. It sets since and until.merged new: manifest
percardThe unit of a rate: hour, day, week or monthgap: rate new: manifest
linkcardMakes the whole card a linknew: manifest

Reported by the plugin, not declared in the manifest: period, occurred_at, dedupe_key and dimensions. They are fields of POST /v1/outcomes.
