Card keys are unique in a factory. Install adds a suggested card only when its key is free, and never overwrites a card an admin has edited. A manifest that declares outcomes fails to install on a service that does not support it.

Aggregations

How the facts in a window become the number on a card. Eight examples.

An aggregation turns the facts in the window into one number. The metric names a default, and a card can set its own. Each example below is a card on the left and the manifest lines that set it up on the right. The two metrics come first, with their facts. The facts do not change from one example to the next.

Which aggregation fits which metric type

Metric typeAggregations
numbersum avg min max count gap last rate
booleancount_true count_false count
string datetime jsoncount
With no facts in the window, sum, avg, min and max have no value and the card shows —. count, count_true and count_false give 0. A card never shows 0 for a number that is missing. A card whose aggregation does not fit its metric type is refused with 422. This is a proposed rule. Percentiles such as p50 and p90 are a gap and are not on this sheet.
03

Windows

The span a card reads. Five examples.

A card window sets the since and until of the read. all sends neither. 7d and 30d end now and start that long before. The service counts a fact at its effective_at: the time it happened, the time it was received, or, for a total, the start of its period.

That rule is simple for increments. It cuts a period for totals. The examples below show the problem and a proposed rule: a window over a total is the last whole periods that have ended.

A · card · 1:1
PRs merged, 7 days
6

now = 25 Nov 17:30 UTC
since = 18 Nov 17:30
until = 25 Nov 17:30
.plugin/plugin.json · automation.outcomes.suggested_cards[ ]
{ "key": "prs-merged-7d", "title": "PRs merged, 7 days",
  "source": { "type": "outcomes", "metric": "prs_merged" },
  "display": "number",
  "window": "7d"2 }

An increment counts at the time it happened, so a rolling window is exact. A PR merged 7 days and 1 minute ago is out, and one merged 6 days 23 hours ago is in. Nothing is cut in half. This is the case the window field was drawn for. The key is the increment prs_merged from the metrics page.

04

Rates

A Count card that shows an amount for each hour, day, week or month. Eight examples.

A rate is a Count card with aggregation: rate and a per. It does not depend on how often the plugin runs. It divides what happened in the window by how long the window is.

The key isThe card showsWindow
incrementThe sum of the facts in the window, divided by the window length in per units. With "of": "count", the number of facts instead of their sum.Rolling, ends now
totalThe sum of the latest report of each period, divided by the length of those periods in per units.Whole periods that have ended
Nothing on this sheet exists in the service. rate, per, of and the whole-period window are proposals. The sums and counts under each card are real: the #818 code produced them. The division is by hand. The service or the client would divide the same two numbers.

Rules at install

These checks keep a bad card from reaching the factory page. A plugin author sees them when the plugin is installed. They are proposed, with the card resource that would run them.

CardInstall
rate on a string, datetime or json keyRefused. With "of": "count" it is allowed.
rate with no perRefused. A rate with no unit has no meaning.
rate with "of": "count" on a totalRefused. It would count period facts.
rate with window: allRefused. The key does not say when counting began, so the length of the window is unknown.
rate over a total with a window that is not whole periodsRefused (windows, example E).

Open questions about rates

R1A day with no report counts as zero (proposed), or is skipped (example H).
R2A rate over a total uses whole periods that have ended (proposed), or the period in progress is included and shown as partial.
R3per: month needs a rule. A month is 28 to 31 days. Proposed: allow it only with a window of whole months (3m, 6m), which the window list does not have yet.
R4The name of for the sum or count choice. of: sum is the default, so most cards leave it out.
R5Who divides: the service (one call, a rate operation on the aggregate route) or the client (two numbers it already gets). The sums and counts above work today either way.
