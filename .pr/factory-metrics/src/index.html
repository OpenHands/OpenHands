Factory metric cards

Component design for the metric cards on a Factory's pages. Each sheet gives an artboard, the dimensions, the tokens, and the mapping from a card definition field to a pixel on the screen. A developer should be able to build any card on these sheets without asking the designer a question.

Written for the Factories prototype (dv/openhands-factories-prototype-a9220b). The Notion pages and the merged backend are inspiration, not a formal spec. Where they disagree, the sheet says so.

Three kinds of field names

Card fields (title, metric, window, compare, display, group_by, link) and card-read fields (value, previous, delta, delta_pct, status, n, as_of, series) come from the Notion "Metrics API" proposal. Metric fields (label, unit, direction, target, kind) come from the same page. The merged backend stores only a type per key today. Sheet 12 lists the difference.

MC-03 · display: "sparkline"

Sparkline

MC-02 plus a 32 px line of the series. Shows shape, not values. The S size is the existing Overview KPI tile.

Required
Everything in MC-02, plus sparkline.bucket (default from window)
Line
1.5 px primary, no fill, no axis, no labels. Last point has a 3 px dot. existing (80 × 26 in S)
Scale
Y from the series min to max with 3 px inset. A flat series draws a mid-height line, never a spike.
Previous
Optional dashed 1 px text-dim line of the previous window, same scale. Only with compare: previous_window.
Gaps
null in series.values breaks the line. Counts are zero-filled, so they never break. Gauges and ratios use null.
Bucket by window
24h hour · 7d day · 30d day · 90d week · 6m week · 1y month · all month. Cap 365 buckets.
Hover
Vertical hairline and a tooltip: bucket start date and value. Keyboard: arrow keys step through buckets.
Backend
merged …/aggregate?group_by=day|week|month returns buckets[{bucket,value,count}] for buckets that have rows. The client fills the empty ones. gap No hour bucket.

MC-04 · display: "percent"

Percent

A share of something. The bar is always 0 to 100%, so two percent cards read the same way side by side.

Required
Everything in MC-02. Unit is percent or ratio.
Support line
"{numerator} of {denominator} {noun}" in the compare slot, 11/14 muted. Needs numerator and denominator on the card-read. new fields The Notion rule: define every ratio's numerator and denominator.
Bar
6 px high, radius 3, track surface-raised, fill primary at 75%. Fill width is the value. No tone color: the status badge carries the tone.
Delta
In percentage points: "▲ 4 pp". Never "+6.9%" for a ratio.
Small sample
n under the minimum: the value stays, the n text turns warning, and the delta chip is dropped.
Backend
merged A boolean outcome key: numerator is operation=count_true, denominator is operation=count. Two calls, same filters.

MC-05 · display: "progress"

Progress to target

A value against a limit or goal. Thresholds come from the metric's target. This is the only card where the bar changes color.

Required
Everything in MC-01, plus metric.target (warn, critical)
Value row
Value, then "of {critical}" as 13/16 muted small text on the same baseline.
Bar
8 px high, radius 4. Fill = value ÷ critical, capped at 100%. A value over critical fills the bar and the badge says "over".
Ticks
1 px, 14 px tall (3 over and under the bar). warn tick text-dim. critical tick danger.
Fill tone
ok primary 75% · warn warning · critical danger. Never rely on color alone: the badge text repeats the status.
Direction
down_is_good (CVEs, spend): thresholds rise with the value, as drawn. up_is_good (coverage): thresholds are floors. Flip the tick order and the fill tone logic.
Backend
gap The merged key registry stores {"type": …} only. #807 made it an object so target, unit, direction, label can be added later without breaking clients.
PUT /factories/acme-sw/metrics/budget_burn
{ "label": "Budget burn", "unit": "usd", "kind": "gauge",
  "aggregation": "last", "direction": "neutral",
  "target": { "warn": 2000, "critical": 2500 } }

MC-06 · group_by: "<dimension>"

Breakdown

MC-02 with the total on top and one row per dimension value. Used for cost by model, failures by cause, tokens by model.

Required
Everything in MC-02, plus group_by
Row
Grid 1.35fr · 1.2fr · auto, gap 10, height 22. Label 12/16 content (ellipsis) · bar 6 px · value 12/16 tabular, right aligned, min 64, then share in 11 px muted.
Bar length
Share of the total, so the bars sum to 100%. Not scaled to the largest row.
Order
By total, largest first. UNKNOWN is always last, in dim italic. (Warp convention, taken by the Notion page.)
Row limit
5 rows, then "Other (n)" summing the rest. The full list opens from the card link or from "View metric".
Ratio metrics
For a ratio grouped by a dimension (tool error rate by tool), the value column shows each group's own ratio and the bar is scaled 0–100%. The headline is the whole-window ratio.

gap The stored outcome row has key, typed value, source, automation_id, run_id. It has no dimension columns. The aggregate group_by takes none day week month only.

MC-07 · group_by: "variant"

Variant comparison

For A/B tests of agent definitions, models, skills, plugins, MCP sets and prompts. It shows the sample size on every row and never declares a winner.

Required
Everything in MC-02, group_by: "variant", a control variant id
Columns
Variant · n · value · delta vs control · guardrails. Row height 34. Header 20, 11/14 muted, 1 px border-subtle under it.
Role badge
control neutral · candidate info. These are the only words used. No "winner", no "best".
Guardrails
Three marks: cost, failure rate, duration. ✓ success when the candidate does not regress. ✕ danger when it does. Tooltip names the metric and the change. The drawing shows a candidate that regresses on duration.
Thin data
Row with n below the minimum: hatched, value —, delta replaced by a dashed "too few runs" badge, n in warning.
Offline check
Optional last row "Benchmark" with the fixed-task-set result. Italic label, info badge "offline".
Backend
gap Needs a variant dimension, and a decision on who assigns variants (Notion open question 2). Needs a rate per group (two aggregates per variant).

MC-08 · group_by: "stage" with aggregation: p50 and p90

Duration split

Time by stage as range bars. Medians hide the tail, so every row shows p50 and p90 together. This is the Notion rule "report durations as median and p90, not mean".

Required
Everything in MC-06, unit: seconds, both p50 and p90 in the card-read per group
Row
Grid 1.25fr · 1.2fr · 76px. Two bars share one track: p90 at 25% primary behind, p50 at 75% primary in front.
Scale
Track = the largest p90 in the card. All rows use the same scale so stages compare by eye.
Order
Process order, not size. The stage order comes from the metric definition.
Value text

Series chart

Bars per bucket. The Notion display list has no full chart, but the merged aggregate already returns buckets by day, week and month, and Warp and Laminar both show bucketed charts. Proposed as an addition.

Required
Everything in MC-02, display: "series", bucket
Plot
Bars with 2 px radius, 4 px gap, primary at 70%. Plot height 128 (min 96). Three horizontal grid lines at 0, mid, max in border-subtle.
Axis
Y labels 11/14 text-dim at the left of the grid lines. X labels: first and last bucket only.
Current bucket
The bucket still in progress is hatched and labelled "in progress" in the tooltip. It is never used for the headline.
Compare
Dashed 1 px line at the previous window's average. Not a second series, to keep the chart readable.
Gaps

Delta and status color

Color says good or bad. Direction says up or down. They are separate.

Delta chip tone: metric.direction × sign of delta

directiondelta > 0delta < 0delta = 0previous is null
up_is_good▲ 4 pp▼ 4 pp● no changechip hidden · "No prior data"
down_is_good▲ $2.10▼ $2.10● no changechip hidden · "No prior data"
neutral▲ 12▼ 12● no changechip hidden · "No prior data"

"No change" applies when |delta_pct| < 0.5. That threshold is a proposal. Arrows point the way the number moved, never the way it should move.

Status badge: from metric.target

Directionokwarncritical
down_is_goodvalue < warnwarn ≤ value < criticalvalue ≥ critical
up_is_goodvalue > warncritical < value ≤ warnvalue ≤ critical
neutralNo status. No badge. target is ignored.
okwarncriticalno datalow n

Order of precedence: no_data, then low n, then the target rule. A card on thin data never shows ok or critical.

Existing mock: the Overview KPI tile uses Badge tone="good" when onTrack and "warn" otherwise, with the text "target {value}". This sheet keeps that look and replaces the boolean with the three-state rule above.

One metric, two cards. The metric says what the number is. A card says how to show it. Cards a and b read the same metric with different windows. Remove card b and the metric and card a stay. Remove the metric while a card uses it, and the service refuses with 409.

Card keys are unique in a factory. Install adds a suggested card only when its key is free, and never overwrites a card an admin has edited. A manifest that declares outcomes fails to install on a service that does not support it.
