How a plugin manifest sets up a Count card. Four examples.

Left is the card as the factory page shows it, drawn 1:1. Right is the part of the plugin manifest that sets it up. A pin joins a manifest line to the part of the card it controls. Pin 5 has no place on the card. Every manifest field on this sheet is new. The backend chips say what the service supports today.

"outcomes": {
  "keys": {
    "reviews_posted": {
      "type": "number",
      "from": "result.reviews",5
      "label": "Reviews posted",
      "description": "Reviews the agent has posted",3
      "unit": "count",
      "direction": "up_is_good",
      "aggregation": "sum"2
    }
  },
  "suggested_cards": [{
    "key": "reviews-total",
    "title": "Reviews posted",1
    "source": { "type": "outcomes", "metric": "reviews_posted" },
    "display": "number",
    "window": "all"2
  }]
}

The simplest Count card. The plugin declares one metric and one suggested card. 1 The title comes from the card. 2 The value is the sum of reviews_posted over the window, and here the window is all. 3 The hint line is the metric description. label names the metric in lists and menus, and the card does not use it. 5 from says where the number comes from: the reviews field of the run result. It has no place on the card. A plugin that posts its own values leaves from out. The card has no link, so it shows no chevron and no hover style.

A gauge is a level, not a total. 2 aggregation: last makes the card show the latest value and not a sum. 4 link makes the whole card a link. A URL outside the app opens in a new tab and shows ↗ in place of ›. The service cannot compute last yet, so this card is not available until that gap closes.

A boolean metric can drive a Count card. 2 count_true counts the true values inside the window. The card window of 7d sets the period, and the metric does not change. The card does not add the window to its title, so the title says it: Passed review, 7 days.

    { "key": "reviews-7d", "title": "Reviews posted, 7 days",b

      "display": "number", "window": "7d" }

One metric, two cards. The metric says what the number is. A card says how to show it. Cards a and b read the same metric with different windows. Remove card b and the metric and card a stay. Remove the metric while a card uses it, and the service refuses with 409.

Card keys are unique in a factory. Install adds a suggested card only when its key is free, and never overwrites a card an admin has edited. A manifest that declares outcomes fails to install on a service that does not support it.
