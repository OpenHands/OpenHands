Design doc · PR #19968 · fix/bounded-event-store

Bounded event store, explicit sequence gaps

The global conversation event store keeps a bounded window of events (cap 2000, history prepends exempt) while preserving its dedupe bookkeeping, and a server-side sequence gap becomes an explicit, user-visible notice instead of a silently contiguous-looking transcript.

1Two failure modes: unbounded memory and silent gaps

On main, use-event-store.ts accumulated every event for the life of the tab use-event-store.ts:66-190 (before) — long agent sessions grew memory monotonically. Separately, session-seq-cursor.ts recorded the next expected sequence but nothing told the user when a range never arrived.

★ The bound is on the list; the dedupe set is never trimmed — trimming it would re-open replay side effects that the set exists to prevent.

2Before → after: the store's own invariants

ⓘ Refetch cannot restore skipped sequence events — the server never resends them (documented in session-seq-cursor.ts's own comment). That is why the fix records and announces gaps instead of attempting a refetch.

3The dedupe set is load-bearing — never trimmed

Trimming the list alongside eventIds would have been the easy bound, but the set guards replay side effects across the whole session; the implementation keeps it full while the list window moves use-event-store.ts (after). This exact point is pinned by the cap/dedupe cases in use-event-store.test.ts.

4Gaps are recorded, not hidden

session-seq-cursor.ts now records skipped ranges session-seq-cursor.ts, and the chat layer renders a notice when a recorded range exists. Short conversations are unaffected: prepend behavior and dedupe are pinned unchanged by the suites.
