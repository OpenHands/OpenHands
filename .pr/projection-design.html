Projection helper · changed

One rule set, two lookup strategies

eventPosition decides whether to append, replace or omit an event. The existing handleEventForUI(event, uiEvents) signature and sequential behavior remain. The new internal batch entry point uses temporary maps for event IDs, streaming IDs and ACP tool-call IDs, updating those maps when a row is replaced. src/utils/handle-event-for-ui.ts:282 · src/utils/handle-event-for-ui.ts:345

PathLookup and ownership
Single eventExisting array scans and one copied result array. Shared conversation and transcript export keep this entry point. src/utils/handle-event-for-ui.ts:326
Batch projectionOne copied array and temporary indexes; a missing key returns directly. No copy or full-prefix scan per event. src/utils/handle-event-for-ui.ts:349

For n retained events, batch reconstruction uses O(n) projection work plus O(n log n) sorting. Streaming deltas keep their existing slot-update path and do not trigger reconstruction. This is a batch bound, not a claim that every live event or keystroke is constant time. src/stores/use-event-store.ts:308

Local scaling probe: 1,000 → 10,000 durable events increased indexed ID reads from 4,000 → 40,000. Backfill medians were 0.226 → 1.573 ms. These synthetic function measurements describe the batch work, not browser input latency. Measurements and limits
