Agent Canvas · issue #17643 · proposed theme migration

Give base color and base typography different names

Canvas’s color token took over Tailwind’s text-base utility. This change renames the color alias to canvas-base, migrates its consumers, and restores the standard font-size utility. The underlying --oh-color-base theme variable keeps the same name and value.

Compatibility decision: custom components that consume generated bg-base or color text-base must migrate. Keeping the old color alias would retain the collision. Runtime theme-variable overrides remain compatible. Start with src/tailwind.css:15.

Before → after

Before: theme alias · After: theme alias · Unchanged cn helper

ConsumerMigration
App surfaces, including opacity variantsbg-base → bg-canvas-base; same color variable
Reject-action foregroundtext-base → text-canvas-base; independent text-sm survives merging
Primary-surface badges and bannerstext-base → text-on-primary; existing same-value alias
Intentional font-size consumerstext-base now supplies 1rem and the default line height instead of accidental color
Chat and onboarding fixed-size inputsKeep text-[16px]; update suppression explanation

Evidence and limits

The regression test failed on the original CSS and passes on this head. node .pr/verify-theme.mjs compiles both source revisions and proves color CSS is identical after renaming, including background/opacity/hover/ring/gradient/text-color cases. Browser checks used the real Canvas UI with MSW data, not a live LLM.

Desktop and 390×844 home screenshots accompany the PR. Chat input styles stayed 16px / 20px; with a temporary 20px host root they stayed 16px / 25px on both revisions. That root override was restored after verification. This does not certify every route or embedding host.

+## Base color and typography utilities
+
+`text-base` is the standard Tailwind font-size utility (1rem with its default
+line height). Canvas's base surface color uses the distinct `canvas-base` token:
+`bg-canvas-base` and `text-canvas-base` resolve to `--oh-color-base`. Text on a
+primary surface can use the existing `text-on-primary` alias.
+
+When updating custom components or an embedding host that uses Canvas's generated
+CSS, migrate `bg-base` to `bg-canvas-base` (including variants and opacity modifiers),
+and migrate any intentional color use of `text-base` to `text-canvas-base` or an
+appropriate semantic color. The old `--color-base` Tailwind alias is removed to
+prevent it from taking over `text-base`; other `*-base` color utilities must use
+`*-canvas-base` when generated by the host's Tailwind build. The runtime theme
+variable `--oh-color-base` and the separate `base-secondary` token are unchanged.
+
+Keep fixed-pixel input sizes explicit when required: replacing `text-[16px]` with
+`text-base` changes its behavior when the host root font size differs from 16px,
+and can introduce a default line height. Check computed styles and class merging
+when migrating typography.
+
