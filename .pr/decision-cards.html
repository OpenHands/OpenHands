Ask once. Answer on the card.

Canvas renders successful ask_user calls as persistent decision cards. An option tap or text-only answer resumes the agent; an ordinary chat reply closes the card too.

2. History settles the card after reload

DecisionCard scans events following the successful observation in the same main/planning scope. An answer event shows the selected option and note; an own user message shows “Answered in chat”; a newer successful ask supersedes the old card. Sender-bearing relayed messages do not answer it.

3. Canvas calls the SDK, not a parallel endpoint

Before this feature, Canvas had no ask-answer service method. The additive method accepts an option index, words, or both: 

AgentServerConversationService.answerAskUser(
  conversationId, askId,
  { optionIndex?: number, text?: string }, runtime?
)
→ new ConversationClient(getAgentServerClientOptions(runtime))
    .answerAskUser(conversationId, askId, answer)

Cloud requires an explicit runtime URL and session key rather than falling back to a local server. This guard is not a claim of live Cloud support: Cloud experimental settings returned no features during verification.
