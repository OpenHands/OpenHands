Inspect the conversation that actually launched

Resources is a read-only conversation tab. It reads the runtime configuration and launch stamp, while using the current profile library only to identify the profile and compare revisions.

★ Editing or renaming a profile must not rewrite the configuration shown for an older conversation. No global settings are substituted for missing runtime data.

Sources: ConversationResourcesService.load:147 · ResourcesPanel:88

1. Runtime data owns the displayed setup

Before this change, the drawer has no Resources surface. The added service projects the published SDK conversation response into a small display model. Profile lookup contributes identity and revision, not current profile defaults.

Source: conversation-resources-service.ts

DataOwnership and boundary

3. Missing information stays explicit

No endpoint, SDK dependency or minimum-server change is introduced. Local calls use the selected backend; Cloud snapshot calls require the actual conversation runtime URL and session key. Environment checks reject late reads after a backend, connection or organization switch.

ACP shows its reported model and MCP data; OpenHands-only categories are unavailable. Cloud reuses profile-field support rules for skills and secret scope. Archived/unreachable runtimes show a retryable read failure; the view does not resume them.

Sources: runtime target and environment checks · category gating
