PR design note · Light+ and Solarized Light

Contrast now follows UI meaning, not the panel underneath

This follow-up addresses the visual QA raised after the light themes landed: status badges, notifications, controls, icons, dividers, and hover states now use shared semantic tokens that remain readable across real Canvas surfaces.

1The UI is more consistent without redesigning the themes

★ Light+ and Solarized Light keep their visual character, while badges clear the 4.5:1 text threshold and interactive form boundaries clear 3:1 in browser measurements.

The follow-up commits audit exposed dark-only assumptions across Canvas and move the light rendering onto theme-aware roles, while explicit dark: compatibility overrides preserve the established Neutral palette. They also close the remaining compositing gaps: a translucent badge no longer changes legibility when its parent card changes surface, shared inputs no longer use the decorative border token, and UI rendered through a portal now keeps the active appearance context.

Sources: status-tone-classes.ts:18, form-control-classes.ts:8, appearance-portal.tsx:10, light-plus.ts:106

Why 133 files changed

The behavioral center is small: theme tokens, shared utilities, and the appearance-preserving portal wrapper. Most remaining files are narrow utility substitutions that give Light+ and Solarized semantic colors while retaining each component's prior Neutral colors through explicit dark: overrides.

  • status badges and inline notices
  • settings and backend forms
  • automation rows and activity states
  • conversation controls and modals
  • icons, dividers, and focus/hover states
  • portal-rendered menus, drawers, and dialogs
  • tests updated to assert semantic classes
