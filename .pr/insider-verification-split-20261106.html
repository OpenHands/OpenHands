2. Voice observation adds state to playback history

Sources: driver, observer and CLI

Before: browser-daemon.mjs:164 · After: browser-daemon.mjs:167 · installMediaObservation:2 · CLI dispatch:3043

browser media retains its existing playback and reduced-motion output. The additive --voice option returns microphone permission and capture outcomes, track state, peer state, inbound audio counters and output element state, including detached Audio instances. The daemon installs its observer before page scripts run.

The Voice projection uses local observation IDs, omits device labels, SDP, ICE addresses and transcripts, and keeps at most 128 observations per kind with explicit dropped counts. Its RTP values establish received media; they cannot establish physical speaker audibility. A collected object retains its last observed state, which alone cannot prove cleanup. The pre-existing plays history is separate from this limit.

3. An explicit rebuild keeps evidence tied to its build

Sources: restart, build identity and evidence reporting

Before: cmdRestart:1089 · assertRebuildAllowed:1092 · rebuildFrontend:1148 · cmdRestart:1197 · Evidence buildId:3539

Ordinary restart still reuses the frontend build. restart --rebuild checks checkout ownership and known peers, stops the owned services, invokes npm run build:app, rejects changing inputs, stamps the successful build and starts the same run again. Existing state, keys and ledger rows remain attached to that run.

recordRebuild() writes attempts to run.json and evidence/build-history.jsonl. New ledger rows include buildId, and reports warn that earlier rows may belong to earlier builds. The operator must end active Voice, then reload and run doctor after success: an already loaded page still holds the previous bundle.

recordRebuild:1140 · Report provenance:3618 · Operating guidance:141

The peer guard has a defined search boundary.

It scans OH_VERIFY_HOME and the selected run’s parent. It cannot discover arbitrary servers or other verification homes; shared machines still need separate checkouts or explicit coordination. Guard scope:1089.
