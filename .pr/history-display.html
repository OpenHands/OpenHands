Read saved messages while the runtime connects

This alternative gives persisted Cloud history its own display query. The ordered runtime-count → App-page query still prepares the socket cursor. Early messages enter the existing event store; they never establish a sequence cursor.

This removes a dependency on runtime latency, at the cost of an additional history read. It is a draft comparison, not a demonstrated healthy-runtime speedup. The PR body contains measured timings and real-browser videos.

+      backend.host,
+      backend.connectionRevision ?? 0,
+      orgId,
+      conversationId,
+    ],

+      backend.kind === "cloud" &&
+      !!orgId &&
+      !!conversationId &&

+          limit: INITIAL_HISTORY_PAGE_SIZE,
+          sortOrder: "TIMESTAMP_DESC",
+          strictPagination: true,
+        },
+      );

+        throw new Error(
+          "Invalid conversation history response: expected page.items to be an array.",
+        );
+      }

+        events: [...page.items].reverse(),

State and compatibility boundaries

OwnerResponsibility
usePersistedConversationHistoryIn-memory Cloud display page, keyed by backend, host, connection revision, organization and conversation. Runtime URL/key rotation does not discard it.
useConversationHistoryCount-before-page ordering and first-connect afterSeq. Initial failures use strictPagination and query retries.
ConversationWebSocketProviderBulk insertion, event-ID deduplication, optimistic-message/model-switch reconciliation, and socket gating.
useLoadOlderEventsObserves the early page without fetching; ignores results from an abandoned backend/org scope.

No new wire contract or Agent Server version requirement. Local and ACP retain the existing fetch path. Cloud standalone and embedded Canvas share the changed provider. Planner loading behavior remains as before. This cache lives only in the current document session; no localStorage transcript is introduced.

Limits and alternatives

The existing 50-event replay overlap remains a bounded-lag workaround. This does not establish a same-log cursor, repair missing webhooks, or compact full-state events. The smaller alternative only skips count for known unavailable Cloud sandboxes. It adds no display query, but cannot help a slow runtime still reported RUNNING.

Evidence

Focused tests cover readable history while count is unresolved, the closed-socket gate, later cursor/reconciliation, short-history pagination, runtime rotation, organization isolation and failed history reads. R01 uses real stored history and runtime responses. The slow-count recording delays only that request by 3 seconds; ordinary timing trials have no video or CPU-profiler overhead. Consult the PR's Why section for the comparison and measurement limits.
