## Reproduction

The main stack was launched with:

```sh
.agents/skills/verify-openhands/scripts/control-openhands launch \
  --new --no-browser --build always --run-id issue-19231-proof \
  --lock-to-cloud https://cloud.example.invalid
```

After arranging the disposable backend and opting out of telemetry, the helper's
run-private `private/launcher-env.json` received
`"AGENT_CANVAS_SKIP_ONBOARDING": "1"`. `control-openhands restart --run <run>`
then restarted the actual npm launcher with that environment. This arrangement
was necessary because the helper's launch environment allow-list does not include
the new variable; the helper itself was kept read-only. `browser reset` created
a fresh browser profile before navigation, captures, and read-only DOM/storage
inspection. `doctor` passed against the running stack and served build.

The two additional CLI variants used the actual production static server:

```sh
node scripts/static-server.mjs --dir build --host 127.0.0.1 --port 65227 \
  --skip-onboarding --disable-telemetry --auth-required \
  --route /api=http://127.0.0.1:18801 \
  --route /server_info=http://127.0.0.1:18801

node scripts/static-server.mjs --dir build --host 127.0.0.1 --port 65232 \
  --skip-onboarding --disable-telemetry \
  --lock-to-cloud https://cloud.example.invalid
```

`control-openhands browser goto <url> --allow-external --run <run>` drove those
owned loopback pages. No response interception, mocked backend, DOM mutation, or
synthetic screenshot was used.
