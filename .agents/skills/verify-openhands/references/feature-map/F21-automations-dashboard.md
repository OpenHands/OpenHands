# F21 — Automations dashboard and actions

The Automate dashboard (`/automations`) is where a user sees every automation at
a glance and acts on one without opening it. It shows four overview tiles, a
search box, a Filters popover (status, trigger, sort), a grid/list view toggle,
a **Drafts** group of saved setup drafts (Resume, Edit, Test, Delete), and Active
and Inactive groups of cards or rows with run health, a recent-runs sparkline
and stats. Each automation has a Play (Run now) button and a kebab menu with Run
now, View, Export, Edit, Turn on/off and Delete; Edit opens the setup page
(`/automations/setup?automationId=<id>`, F22) in edit mode. The page sits in
a Dashboard/Templates sub-page shell. It is reached from the sidebar, the command
menu or a pinned home route, and it only exists when the automation interface
manifest from `@openhands/extensions` is admitted.

Source: `src/routes/automations-list.tsx`, `src/components/features/automations/` (`automation-card.tsx`, `automation-list-row.tsx`, `kebab-menu.tsx`, `build-automation-menu-items.tsx`, `delete-confirmation-modal.tsx`, `automation-view-toggle.tsx`, `empty-state.tsx`, `dashboard/`), `src/components/features/manifest/manifest-subpage-layout.tsx`, `src/components/features/manifest/manifest-overview-tiles.tsx`, `src/manifests/automation-insights.ts`, `src/manifests/automation-interface.ts`, `src/hooks/query/use-automations.ts`, `src/hooks/use-open-automation-editor.ts`, `src/hooks/use-start-automation-setup.ts`, `src/utils/automation-state.ts`, `src/hooks/use-pinned-home-route.ts`, `node_modules/@openhands/extensions/automations/interface.json`.

## Sub-features

- `F21.sidebar-entry`: the sidebar **Automate** item opens `/automations` with the heading **Dashboard** and the Automate sub-page aside.
- `F21.command-menu`: the command menu offers **Automations** ("Review scheduled and webhook automations."), also found by the keywords automate, cron, schedule, webhook and jobs; choosing it opens `/automations`.
- `F21.pin-home`: the pin on the sidebar Automate item makes `/` redirect to `/automations`; unpinning restores the normal home.
- `F21.subpage-nav`: Dashboard and Templates sub-pages appear in a left aside from 1024 px up and in a horizontal strip below that (phones and tablets); the current page has `aria-current="page"`.
- `F21.manifest-404`: without an admitted automation interface manifest, `/automations` is a 404 from the layout error boundary, and all Automate entry points, including the Home checklist and recommendations, are hidden without error toasts. Known failure: Canvas hides the sidebar entry but leaves a dead Home checklist link and raises two manifest errors ([#18210](https://github.com/OpenHands/OpenHands/issues/18210); [draft fix PR #18212](https://github.com/OpenHands/OpenHands/pull/18212)).
- `F21.health-loading`: while the health check runs, the page shows the title and three card skeletons.
- `F21.list-loading`: once the backend is healthy, the header, tiles and controls render at once while three card skeletons stand in for the list until the first page arrives.
- `F21.backend-unavailable`: when the health check fails, the page shows **Automations Unavailable** with a Retry button.
- `F21.list-error`: when the list request fails with nothing cached, the page shows **Failed to load automations** with Retry.
- `F21.add-menu`: the header **Add Automation** menu offers **Create Automation** and **Import automation**; Create Automation opens the guided setup page at `/automations/setup` (F22).
- `F21.empty-state`: with zero automations and zero saved drafts the page shows **No automations configured**, the "Create an automation" instructions, a docs link, **Create Automation** (opens `/automations/setup`, F22, without creating a conversation) and the Recommended automations rail; the view toggle is disabled.
- `F21.empty-rail`: a Recommended automations card on the empty dashboard opens its template setup at `/automations/new/<template-id>` (F22 owns the setup flow). A mouse drag scrolls the rail without opening the card it starts on, and a drag released outside the rail does not swallow the next keyboard or touch activation. This rail has no dismiss X and stays shown when Home's rail was hidden (F03.recommended-rail-dismiss).
- `F21.overview-tiles`: four tiles summarize the automations the groups list from the loaded org list (hidden DRAFT test automations from a draft Test are left out): Automations (`N active`), Needs attention (`Latest run failed` or `No latest-run failures`; an enabled automation counts when its latest run is Failed or its task outcome is `failed` or `blocked`, while Partial and Needs review do not count), Total runs and Average duration.
- `F21.search`: the search box narrows the visible automations client-side by name, prompt, any of their repositories or model, and the saved drafts by name, prompt, kind or trigger; the tiles do not change.
- `F21.filters`: the **Filters** popover filters by status (All / Active / Needs attention / Disabled) and trigger (All / Scheduled / Event-driven), counts non-default choices in a badge and offers **Reset all**; it stays open while the user changes several choices.
- `F21.sort`: Sort (Latest run / Most runs / Name) orders automations inside each group and counts as a non-default choice.
- `F21.filtered-empty`: when nothing matches, **No automations match these filters** and **Clear filters** appear; Clear filters resets search, status and trigger but keeps the sort.
- `F21.view-toggle`: the view-mode menu switches Grid and List; the choice survives a reload.
- `F21.card-grid`: a grid card shows name, prompt preview, one folder pill per repository (the `owner/repo` name, the full address on hover) and trigger pills, sparkline, a status strip (latest run status, summary, relative time, or **No activity yet**) and Runs / Recent success / Avg. duration stats. While the latest run is Pending, Running or Failed the strip also shows the run's current phase as the automation service reports it (for example `Installing dependencies`, `Agent is working on the task`; the full text in a tooltip); a finished successful run shows none.
- `F21.list-row`: a list row shows a health dot, name, schedule or event, relative last run, run badge, sparkline, Play and kebab; its link is labelled `<name> <status>`.
- `F21.row-tooltip`: hovering a list row shows a preview card with the name, Trigger, Status and, once it has run, Last run and Task (the run summary); the Play button's tooltip reads **Run now**.
- `F21.summary-hovercard`: hovering a grid card's truncated run summary shows the full summary in a hovercard.
- `F21.sparkline-deeplink`: a sparkline bar links to `/automations/<id>?run=<runId>`, which opens the detail page with that run highlighted.
- `F21.open-detail`: kebab **View**, the row link, a card click and Enter on a focused card all open `/automations/<id>`.
- `F21.load-more`: past 50 automations a **Load more** button fetches the next page and disappears when everything is loaded.
- `F21.git-sync-button`: the header **Git Sync** button (manage permission; always on local) opens `/automations/git-sync` (see F24).
- `F21.kebab-menu`: the **Automation actions** menu lists Run now, View, Export, Edit, Turn on/Turn off and Delete, closes on Escape or an outside click, and flips above the trigger near the viewport bottom.
- `F21.run-now`: Play or kebab **Run now** on an enabled automation dispatches a run with the toast **Automation dispatched**; the card moves through Pending/Running to the result. Both are disabled on a disabled automation.
- `F21.run-now-error`: a failed dispatch shows exactly one error toast with the API message; when the automation is gone (`Automation not found`), its card then drops out of the dashboard without a reload.
- `F21.toggle`: kebab **Turn on** / **Turn off** flips the enabled flag immediately (no confirmation on the dashboard) and moves the automation between the Active and Inactive groups.
- `F21.edit`: kebab **Edit** opens the setup page in edit mode (`/automations/setup?automationId=<id>`) prefilled from the automation, including every saved repository, with **Test**, **Save** and **Close** in its toolbar; Save sends one PATCH and toasts **Automation updated**, Close returns to `/automations` (field-level editing is F23). On a prompt or plugin automation whose automation service advertises `repoUpdate`, repositories can be removed or added (Repositories **+**) and Save sends the changed list as `repos`, keeping each saved repository's provider; reopening Edit and the card show the saved list. Against a service without `repoUpdate` they are read-only with **Can't be changed for this automation**. For a script (tarball) automation it summarizes the saved bundle (**Existing code bundle** with the upload id) instead of a code editor, from the kebab and on a cold load alike, and saving keeps that bundle (F23.edit-save).
- `F21.export`: kebab **Export** downloads `<name-slug>.automation.json` with `version`, `kind: "automation"` and the spec.
- `F21.delete`: kebab **Delete** asks `Delete "<name>"? This cannot be undone.`; Cancel and the X keep it, Delete removes it for good, and Escape dismisses the dialog.
- `F21.saved-drafts`: saved setup drafts (#17242) appear in a **Drafts** group above Active/Inactive, one row each with the name (Resume), a pencil (**Edit**), Play (**Test draft**, tooltip **Test Run**; disabled for event-triggered or non-dispatchable drafts) and a trash (**Delete draft**). Resume and Edit open `/automations/setup?draftId=<id>`; Test dispatches a test run (toast **Test run started.**) on a materialized DRAFT-state automation that the groups do not list; Delete asks **Delete draft?** (`Delete “<name>”? This removes the saved setup draft, but does not delete any final automations.`) with Cancel / **Delete draft** and toasts **Draft deleted.**, also removing the draft's materialized test automation. The confirmation is the named modal dialog **Delete draft?** (the automation delete dialog with draft copy): it opens with focus on Cancel, keeps Tab inside, closes on Escape, X, Cancel or a backdrop click and returns focus to the trash button.
- `F21.phone`: at 390 px the dashboard has no horizontal overflow, tiles wrap 2×2 and the kebab menu stays inside the viewport.

## How to get to it (user POV)

- Sidebar **Automate** (`sidebar-automations-link`); hovering it reveals the pin (`sidebar-pin-home-toggle-automations`).
- Direct URL `/automations`; the Templates sub-page is `/automations/templates` (F22).
- Command menu (`Control+k`/`Meta+k` or `command-menu-trigger`): type `Automations` or a keyword such as `cron`, press Enter.
- With Automate pinned, `/` (logo, a bare visit) lands on `/automations`.
- Sub-page navigation: `automations-navbar-desktop` (aside) or `automations-navbar-mobile` (phone strip), links `automations-navigation-list` and `automations-navigation-templates`.
- Header **Add Automation** (`automations-add-automation`) → **Create Automation** (`automations-add-automation-create`, `/automations/setup`, F22) or **Import automation** (`automations-import-automation`, F22); on the empty dashboard, the Recommended automations rail cards (`recommended-automation-rail-card-<id>`).
- Getting-started checklist item **Schedule a task** links to `/automations` (onboarding checklist family).
- Saved drafts: the **Drafts** group rows (`automation-setup-draft-resume-<draft-id>`, `-edit-`, `-test-`, `-delete-`).
- Per automation: Play (`automation-run-now-<id>`, name "Run now") and kebab (name "Automation actions") on each card or row; the card itself and the row link open the detail page (F23).

## Driving it with control-openhands

Preconditions:

- Baseline state (launched, doctored, `onboard --skip` done) with an active LLM profile for Run now (`control-openhands llm preset deepseek`, or `--api-key-file <file>` when the key is in a file).
- No automations exist (`control-openhands api GET /api/automation/v1` shows `"total": 0`); the recipes start from the empty state.
- Fixtures are imported through **Add Automation → Import automation** (F22 owns that flow; here it only arranges). Create the files first; each command prints the path to upload (`$OH_VERIFY_RUN/evidence/_fixtures/<name>`):
  `control-openhands fixture file --name qa-f21-alpha.automation.json --content '{"version":1,"kind":"automation","spec":{"name":"QA_F21 Alpha","trigger":{"type":"cron","schedule":"0 0 1 1 *","timezone":"UTC"},"enabled":false,"prompt":"Reply with the single word: pong. Do not run any tools."}}'`,
  `control-openhands fixture file --name qa-f21-beta.automation.json --content '{"version":1,"kind":"automation","spec":{"name":"QA_F21 Beta","trigger":{"type":"event","source":"github","on":"pull_request.opened"},"enabled":false,"prompt":"Beta event-driven QA fixture; never runs."}}'`,
  `control-openhands fixture file --name qa-f21-fail.automation.json --content '{"version":1,"kind":"automation","spec":{"name":"QA_F21 Fail","trigger":{"type":"cron","schedule":"0 0 1 1 *","timezone":"UTC"},"enabled":false,"prompt":"Reply with the single word: pong.","timeout":1}}'`.
  The yearly cron (`0 0 1 1 *`) keeps a turned-on fixture from firing on its own.
- Selectors below avoid run-specific ids: `[data-testid^="automation-card-"] >> has-text=<name>` (grid) and `[data-testid^="automation-list-row-"] >> has-text=<name>` (list). The kebab menu renders in a portal with no test ids; scope its items as `role=list >> has-text=Export >> role=button[name="..."]`.

## Gotchas

- Both sub-page navs are always in the DOM (one hidden by CSS). Unscoped `testid=automations-navigation-templates` is a strict-mode violation; scope it with `testid=automations-navbar-desktop >> ` or `testid=automations-navbar-mobile >> `.
- The pin toggle is invisible until the Automate item is hovered on a fine pointer: `browser hover 'testid=sidebar-automations-link'` before clicking it. The pin is stored per backend and org in `localStorage` (`oh:pinned-home-route:<backend>:<org>`); unpin before leaving the run.
- The Filters popover's status and trigger choices do not apply to the Drafts group: with status Active and trigger Event-driven, a cron draft stays listed and the filtered empty state does not show (search does filter drafts). Intent undocumented in #17242.
- The setup page's success toast (`Automation updated`) covers its toolbar's Test, Save and Close and does not time out while the pointer rests on it; a click there fails with "subtree intercepts pointer events". Move the pointer away (`browser hover` on a form field), wait about 5 s, then click.
- `testid=dropdown-trigger` is reused by the backend selector, the Filters button and every inner dropdown. Always scope it (`testid=automations-filters >> testid=dropdown-trigger >> nth=0` for the Filters button, `testid=automations-filter-status >> testid=dropdown-trigger` for a field).
- The Filters popover stays open while choices change and closes only on a click outside it or on the Filters button; Escape does not close it. Open, it covers the right part of the list (in list view the first rows' Play buttons): close it with a click on `role=heading[name="Dashboard"]` before clicking row or card controls.
- A card whose automation was deleted elsewhere stays on the dashboard after its Run now fails with `Automation not found`. Expected: the card drops out once the dispatch returns 404. Known failure: nothing refetches the list after the failed dispatch, so the card stays until a reload or another list refetch (still there 2 minutes later) ([#18062](https://github.com/OpenHands/OpenHands/issues/18062)).
- The delete confirmation has no test ids; scope it as the named dialog `role=dialog[name="Delete automation"]`. It opens with focus on Cancel.
- Delete closes the dialog at once and shows no success toast; confirm with a reload. Turn off on the dashboard never asks for confirmation (home cards do).
- `browser drag` starts from the source's current box without scrolling it into view: below the fold (the empty dashboard's rail at phone width) run `browser scroll '<card selector>'` first, or the drag moves nothing.
- The kebab menu has no test ids; `role=list >> has-text=Export` is the reliable scope. A card's own **Run now** has the same accessible name as the kebab item, so scope Play to the card.
- Imported automations are always disabled (`Import automation` says so), and Run now is disabled until you **Turn on**. Use the yearly cron `0 0 1 1 *` or an event trigger so an enabled fixture never fires by itself, and turn it back off.
- Run now uses the active LLM profile when the automation's model is `Active profile`. A successful run creates a conversation titled `<automation name> — <UTC timestamp>` that stays after the automation is deleted. Delete it separately (`control-openhands conversation list`, conversations family) to leave the run clean.
- A timeout of 1 s does not fail fast: the run sat in `Installing dependencies` and failed with `Timed out: command timed out or was killed` about 3-4 minutes after dispatch. Budget for that when you need a failing run for Needs attention.
- The Automations tile counts only loaded pages: with 51 automations it reads `50` until **Load more** is clicked, although the API `total` is 51.
- The row health dot and label reflect the latest run only; a disabled automation with no runs reads `No activity yet`, not `Disabled`.
- In grid view a cron automation without `schedule_human` shows the pill `cron`, while list view shows the raw expression (`0 0 1 1 *`).
- The view mode persists in `localStorage` (`openhands-automations-view`), and the toggle is disabled when the org has no automations. Switch back to Grid before deleting the last automation, or the next run starts in List.
- Filters, search and sort are page state only: a reload resets them.
- `service stop automation` stops only this run's automation service; `restart` brings the whole stack back with the same state and the browser on the same page. Run `control-openhands doctor` afterwards.
- The **Automation dispatched** toast lasts only a few seconds: run `browser wait-text 'Automation dispatched'` right after the click, not after a long `--observe` window.
- `browser screenshot --full-page` at phone width does not capture below the fold, because the page scrolls inside the main pane; screenshot sections or use `bbox`.
- Known issue [OpenHands/automation#246](https://github.com/OpenHands/automation/issues/246) (`F21.backend-unavailable`, `F21.list-error`): The report says only that local automation returns 404. It omits the URL, UI action, release and launcher/service setup, so a normal successful dashboard visit would not reproduce or resolve its unknown branch. Ask for those exact prerequisites before writing a failing recipe.
- Known issue [OpenHands/automation#347](https://github.com/OpenHands/automation/issues/347) (`F21.card-grid`, `F21.overview-tiles`): per-automation run-summary reads lack an aggregate contract, and the report describes a 30 s shared-resource stall with HTTP 500 plus SQLite pool settings that do not apply. A failing recipe needs the original database/lock workload and redacted service-log/HAR timing evidence, which the report withholds. Successful summary reads under the Canvas request throttle do not establish those backend contracts.
