# F28 — Automation setup page

The setup page is the one form for making and changing automations outside the
template dialog. **Add Automation → Create Automation** opens it blank at
`/automations/setup`; a saved draft reopens at `/automations/setup?draftId=<id>`;
kebab **Edit** opens an existing automation at
`/automations/setup?automationId=<id>`. The form collects Name, a Prompt (or
Custom Python with entrypoint and setup script), model (LLM profile) and
repositories, a Schedule or Event trigger, and optional plugins and timeout.
A docked composer under the form can ask the agent to fill it. Create mode's
toolbar has **Save draft**, **Test** and **Create Automation**; edit mode's has
**Test**, **Save** and **Close**. A server-backed draft carries the server's
validation result and test runs; Create turns it into a real, enabled
automation and removes the draft.

F22 keeps `F22.agent-assisted-setup` (the end-to-end agent, plugin, phone and
draft-Test recipes); F23 owns edit mode (`F23.edit-*`, including Test and the save state on the edit
page). This family gives each create-mode behavior its own ID so a pass can fail one without
failing the others.

Source: `src/routes/automation-setup-new.tsx`, `src/components/features/automations/setup/` (`automation-setup-panel.tsx`, `automation-setup-prompt-stack.tsx`, `automation-setup-draft-service.ts`), `src/utils/automation-repo-sources.ts`, `src/hooks/use-start-automation-setup.ts`, `src/hooks/use-open-automation-editor.ts`.

## Sub-features

- `F28.open-blank`: Create Automation opens `/automations/setup` with Name pre-filled **New Automation** (placeholder `Standup digest`), an empty Prompt, Schedule selected with Daily at `09:00` in `America/New_York` (the default, whatever the browser's time zone), the docked composer (`Need help creating an automation?`) and no new conversation. The save state already reads **Unsaved changes** and the toolbar **Test** is disabled. Neither the Prompt nor the Custom kind offers an agent profile (`automation-agent-profile` count `0`); both show the LLM profile pill `automation-setup-model` (Prompt inside the prompt card, Custom under **Entrypoint and setup**), and the Schedule and Event cards read `Run on an interval or at a set time` and `Run when an integration or webhook sends an event`.
- `F28.kind-toggle`: the button beside the Prompt label switches between Prompt and **Custom** (Custom Python). Custom shows a generated Python script that calls `AUTOMATION_CALLBACK_URL`, and **Entrypoint and setup** reveals Entrypoint `python3 main.py`, Setup script path `setup.sh` and a no-op setup script; the LLM profile pill stays below the script, and the profile picked there is saved with the draft as `model` (left on **Active profile**, nothing is sent). Switching back shows the Prompt again.
- `F28.schedule-presets`: in create mode the Frequency control (the same control as on the edit page, whose presets and saving F23 owns as edit-schedule and edit-cron) starts on Daily at `09:00`, and switching presets fills create-mode defaults: Once a date-time at the next whole hour today, Weekly Monday, and Custom the cron of the preset it replaces (from Weekly, Monday at `10:30` it reads `30 10 * * 1`; Weekdays `30 10 * * 1-5`, Hourly `0 * * * *`, Once on 17 October at `09:00` `0 9 17 10 *`). Clicking Custom again keeps a cron already typed there; leaving Custom for a preset and coming back starts from that preset again. Every preset keeps the 13-entry time zone select.
- `F28.event-trigger`: choosing **Event** replaces the schedule with Event source (default **GitHub**, sent as `github`; its menu lists, by name, the event sources the automation service reports in `eventSources` (Azure DevOps, Bitbucket Data Center, GitHub, Jira Data Center when built-in sources are enabled), or, when it reports none or has not answered, the automation service's built-in providers GitHub, Azure DevOps, Bitbucket Data Center and Jira Data Center, plus **Custom**), Event key (default `issue_comment.created`; its suggestions are the selected source's event types, see event-types-by-source below), **Add Filter** (one free-text filter input), **Ask Agent**, the notice `Event sources need a public URL to deliver webhooks to this instance.`, and a **Test event payload** pre-filled with a JSON object for that source and key. A source the backend has not registered (menu **Custom**, then a typed name such as `linear`, `slack`, `gitlab` or `jira`) adds **Register this as a custom webhook source**, checked by default; a typed known source (`jira_dc`, `bitbucket_data_center`, `azure_devops` with the fallback list) shows its name (`Jira Data Center`) and no such section. The Event source menu closes on an outside click, a choice or Escape; Escape sets the toggle's `aria-expanded` back to `false` and returns focus to the toggle, at desktop and phone widths.
- `F28.event-types-by-source`: the Event key suggestions (`automation-setup-event-key-options`) follow the selected source from the service's `eventTypesBySource`: GitHub `issue_comment.*`, `issues.*`, `pull_request.*`, `pull_request_review.*`, `push`, `release.*`; Jira Data Center `comment_created` … `jira:issue_updated`; Bitbucket Data Center `pr:comment:added` … `repo:refs_changed`; a source without a catalog (Azure DevOps, a custom source) none. Choosing a source that does not deliver the current key switches the key to that source's first type (back to GitHub that is the pattern `issue_comment.*`); a source without a catalog keeps the key. The untouched default test payload follows the source: Jira Data Center sends `webhookEvent`, Bitbucket Data Center `eventKey` set to the key, other sources `{source, event, action: "test"}`; an edited payload is kept. A picked Jira DC `comment_created` or Bitbucket DC `pr:opened` saves as `trigger: {type: "event", source: "jira_dc", on: "comment_created"}` / `{source: "bitbucket_data_center", on: "pr:opened"}`. A service that reports no event sources (the pinned local automation) offers no suggestions at all.
- `F28.timeout`: **Add Timeout** adds an optional **Timeout seconds** number field with a remove button; `1800` saves and the draft reads **Ready to test**.
- `F28.draft-save`: **Save draft** works on any form, valid or not; the first save replaces the URL with `?draftId=<id>`, shows the **Draft saved** bar (relative time, **View test runs**, **Test**) and the toast `Draft saved in this conversation.`, and the save state reads **Saved just now**. The draft appears in the dashboard Drafts group (F21).
- `F28.draft-validation`: the server validates on save, not on blur. An invalid draft is still saved (`dispatchable: false`) and its first error replaces **Ready to test** in the draft bar: an empty prompt shows `Field required` (also under Prompt), a bad custom cron shows `Value error, Invalid cron expression: every day`. A field error stays until the next save. **Test** stays enabled on a saved invalid draft: it saves again, opens **Test runs** with the same error in a red alert and dispatches nothing. The current validation error comes before any test status: after a successful draft Test the pill reads **Latest test passed**, and once an invalid cron is saved it reads the cron error (also after a reload, at desktop and phone widths) while the API marks the draft non-dispatchable.
- `F28.draft-save-error`: a draft the server refuses outright (a timeout above 1800 returns `422`) sets the save state to **Save failed** and shows one error toast with the reason the API gives (a timeout of 1801 reads `Value error, timeout must not exceed 1800 seconds (30 minutes)`). The draft bar drops its validity pill (no stale **Ready to test**) until a save succeeds.
- `F28.required-before-test`: Test and Create check locally first and send nothing when a required field is empty: `Add a prompt before continuing.` (Prompt or Plugin kind), `Add a plugin source before continuing.`, `Add Python code before continuing.`, `Add an entrypoint command before continuing.`, `Add a setup script path before continuing.`, `Add a setup script before continuing.`; an event Test with a payload that is not a JSON object shows `Enter a valid JSON object before testing this event automation.` A blank Name is not an error: it is derived from the prompt.
- `F28.test-gated`: in create mode **Test** stays disabled until the draft is saved and unchanged since; editing any field after a save disables it again until the next **Save draft**.
- `F28.draft-test`: **Test** on a saved, valid draft opens **Test runs** (with **Back**), shows `Test run started.` and a Pending row; it runs a hidden disabled copy of the draft, not a dashboard automation. Expected: the row reaches Successful or Failed by itself. Known failure #18263 (reproduced again 2026-10-27 on a Custom Python draft, automation 1.26.0): the row stays Pending and the page does not poll the runs after the first request. Known failure (reproduced once 2026-10-17, SDK1.55.1, [OpenHands/software-agent-sdk#6024](https://github.com/OpenHands/software-agent-sdk/issues/6024)): gracefully restarting an owned deferred-init Agent Server during the Custom Test command can leave its persisted BashCommand without final BashOutput. Reopening Test runs → View logs showed `RUNNING` / `(no output)`; two postrestart BashOutput searches returned zero. Expected: an interrupted command retains terminal status/output and Logs stops implying it is running. This is the shared F23/F28 RunLogsModal consumer; native Terminal, SIGKILL, phone and fix attribution were not verified.
- `F28.create`: **Create Automation** creates the automation (a Custom Python automation is created on, with the model picked in its LLM profile pill; a Prompt or Plugin automation is created off, with an **Inactive** badge), navigates to `/automations/<id>` (a Custom Python automation shows **Script**) with the toast `Automation created.`, and removes the draft from the dashboard Drafts group.
- `F28.repositories`: on the Prompt kind, **Repositories** **+** (`automation-setup-repository-add`) opens a menu with **Search repositories** and **Custom**. Custom opens **Add Repositories** (`Repository`, placeholder `owner/repo`, **Add** disabled until something is typed); each address becomes a chip with a remove button. The draft and the create request send `owner/repo` as `{url, provider: "github"}` and a full URL (`https://gitlab.com/...`) without a provider; the detail page lists both as `owner/repo`. With no Git provider connected on a local backend the menu lists no repositories and an info icon beside **+** explains `Configure a provider token secret, e.g. "GITHUB_TOKEN", in the Settings page to see repo options.` The row and its menu fit at 390 px. The **+** menu and the model pill's popover (`automation-setup-model-popover`) close on Escape, also when focus is in the menu's **Search repositories** field: `aria-expanded` goes back to `false` and focus returns to their trigger. An outside click also closes them.
- `F28.repository-providers`: with a connected Git provider the menu lists its repositories (`automation-setup-repository-option-<name>`) and searches the provider. Each option stays on one line: when a name does not fit, the organization/project part shortens with an ellipsis first so the repository name stays visible, and the option's hover title is the full name. With more than one connected provider whose repositories the automation service clones (`repoProviders` in `/api/automation/v1/capabilities`; 1.26.0 lists Azure DevOps, Bitbucket, GitHub and GitLab), a **Git provider** choice (`automation-setup-repository-provider`) switches lists, GitHub first. A GitHub pick is stored as `owner/repo`; other providers' picks as the URL on their host, a connected self-hosted host also sending its `provider`. A connected provider the service does not clone, or one whose host the server does not report, shows `Automations can't clone <provider> repositories yet.` (`automation-setup-repository-unsupported`).
- `F28.error-contrast`: the draft bar's error pill and the Test runs error alert use the theme's error color (`text-feedback-error`) and reach at least 4.5:1 in all five color themes. Their tints follow the same theme error color: the pill a 5% tint over the draft bar surface, the alert a 10% tint with a 40% border.

## How to get to it (user POV)

- Dashboard header **Add Automation → Create Automation** (`automations-add-automation`, then `automations-add-automation-create`): blank create mode. Every create recipe below starts here.
- Empty dashboard **Create Automation** (`automations-empty >> automations-create-automation`): the same blank form (`F21.empty-state`).
- Dashboard Drafts group: name or **Resume** (`automation-setup-draft-resume-<draft-id>`) and the pencil (**Edit**, `automation-setup-draft-edit-<draft-id>`) open `?draftId=<id>`.
- Kebab **Edit** on a dashboard card or the detail page header: edit mode (`?automationId=<id>`, `F21.edit`, `F23.edit-open`).
- A direct URL with `draftId` or `automationId` (see the cold-load gotcha).

## Gotchas

- A toast can cover the toolbar (Save draft, Test, Close) and stays while the pointer rests on it, so the next toolbar click times out ("subtree intercepts pointer events"). After each save, `browser hover` a form field (for example `testid=automation-setup-name`) before clicking the toolbar again, as F22's Gotchas say.
- Drive inputs with `browser fill`: setting `.value` from `browser eval` does not reach React state for every field, and a save then sends the old value.
- Change one field per Save draft when checking a validation message: a save shows only the first server error, so two edits in one save hide the second.
- A cold load of `/automations/setup?draftId=<id>` or `?automationId=<id>` (a reload or a typed URL) opens the form: re-checked 2026-10-14 on a `control-openhands launch` of main with this family (both read their Name back). An earlier instance of unknown build stayed on **Loading saved draft…** for more than 20 s; if that returns, compare with opening the same draft from the dashboard.
- The draft bar duplicates the prompt error: `Field required` appears both under Prompt and in the bar.
- Kebab **Edit** on a Custom Python (tarball) automation shows the **Existing code bundle** summary, not the code editor, and Save keeps that bundle without asking for upload-time fields (`F23.edit-open`, `F23.edit-save`).
- With no menu open, Escape on the setup page does nothing, by design (`F23.edit-close`); it closes only an open Repositories **+** menu, model popover or Event source menu.
