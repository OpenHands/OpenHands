# F13 — Agent profiles

Settings → Agent is a library of named agent profiles. Each profile is either an
OpenHands agent (an LLM profile, a system prompt, a Model Router, a tool set,
parallel tool calls, MCP-server and secret scopes, condenser, verification and
skills) or an ACP external agent (a preset such as Claude Code, Codex, Gemini
CLI, Pi or OpenCode, its launch command, a model the agent itself reports, and
provider credentials). One profile is active; new conversations started from
Home launch from it by id, the seeded `default` included. On a local backend the
OpenHands `default` shares its LLM, MCP servers, secrets and skills with the
global pages (the active LLM profile, the servers switched on in MCP Servers,
every secret, the Skills page list), cannot be renamed or deleted, and is the
template a new profile copies its other settings from.

Source: `src/routes/agent-profiles-settings.tsx`, `src/routes/agent-settings.tsx`, `src/components/features/settings/agent-profiles/`, `src/components/features/settings/acp-credentials-section.tsx`, `src/components/features/settings/acp-conflict-warnings.tsx`, `src/components/features/settings/acp-auth-status-banner.tsx`, `src/constants/acp-providers.ts`, `src/constants/acp-brand-marks.ts`, `src/hooks/query/use-acp-model-discovery.ts`, `src/hooks/query/use-skill-catalog.ts`, `src/hooks/mutation/use-create-conversation.ts`, `src/hooks/mutation/resolve-conversation-launch.ts`, `src/hooks/mutation/use-new-conversation-command.ts`, `src/hooks/mutation/sync-agent-profiles.ts`, `src/hooks/use-chat-input-llm-profile-state.ts`, `src/api/agent-profiles-service/profile-field-support.ts`.

## Sub-features

- `F13.list`: under **Available Profiles**, rows (sorted by name) show the profile name, then its LLM profile (OpenHands) or `ACP (external subprocess)`, an **Active** badge on the active profile and a `...` menu (Edit, Set as active, Delete).
- `F13.create`: **Add agent profile** opens the editor; Save toasts `Profile "<name>" created` and the row is listed after a reload. A new OpenHands profile starts from `default`'s system prompt, Model Router, parallel tool calls, tools, condenser, verification and skills; its MCP servers and secrets start unrestricted and its LLM picker on the active LLM profile.
- `F13.name-validation`: a fresh Add editor's empty name is not flagged (Save disabled); once typed, an empty or malformed name marks the field invalid (red rule) and disables Save; a name another profile already has also marks the field invalid, shows a red taken-name message about agent profiles under it (the rule stays grey) and disables Save (Edit accepts the profile's own name).
- `F13.editor-no-llm`: with no LLM profiles, an OpenHands profile shows `Create an LLM profile first to define an OpenHands agent.` and Save toasts `Select an LLM profile for this agent.` without creating anything.
- `F13.openhands-options`: OpenHands profiles offer an LLM profile dropdown right under the agent type (the active LLM profile by default), a **System prompt** choice (`OpenHands default`, `Default + your instructions` or `Custom persona`, each saved on the profile), **Parallel tool calls** (default 1, minimum 1) and **Tools**: `Standard tools` (default) lists the server's standard set read-only, `Choose tools` turns the server's tool catalog into switches; values persist and reopen.
- `F13.edit`: Edit reopens the stored values with Save disabled until something changes; renaming keeps the profile id; Back and Cancel leave without saving. On a local backend the `default` name field is disabled with `The default profile can't be renamed or deleted.` under it.
- `F13.stale-llm-ref`: editing a profile whose LLM profile no longer exists preselects the active LLM profile and enables Save, so saving heals the reference; launching it unhealed keeps the profile and runs the active LLM profile (`launched_agent_profile.llm_profile_ref`).
- `F13.set-active`: **Set as active** toasts `Switched to profile "<name>"`, moves the Active badge and is disabled on the active row.
- `F13.active-drives-conversation`: a conversation started from Home, or with `/new` typed in a conversation's composer, after activation launches from that profile (its id and settings are stamped on the conversation: `launched_agent_profile.agent_profile_id`, tools, parallel tool calls, condenser, router, skills); with an ACP profile active, `/new` starts an ACP agent. The seeded OpenHands `default` launches by id the same way, on the active LLM profile.
- `F13.llm-pill-precedence`: the Home LLM pill shows the active agent profile's LLM. On a named profile it shows that profile's own LLM profile, a pick there saves to the profile (the active LLM profile is unchanged) and the launch runs it; on `default` it shows the active LLM profile and a pick activates another one, which `default` then runs.
- `F13.default-shared`: on a local backend the OpenHands `default` editor shows every section, with notes where it shares a global page: LLM (`The default profile uses the active LLM profile. Picking another one here makes it active.`), MCP servers (`The default profile uses the servers switched on in MCP Servers. …`), Secrets (`The default profile always has every secret.`, no picker) and Skills (`The default profile's skills are the Skills page list. …`).
- `F13.profile-router`: an OpenHands profile has a **Model Router** dropdown: `Off` (default for a new profile when `default` has none) or one of the saved routers; saving stores `meta_profile_ref` and `enable_classify_and_switch_llm_tool`, and a launch gets `route_task_to_model` (plus the first-message instruction while F12's **Run on first message** is on). A router that no longer exists stays selected with a red warning; a profile with routing on but no router named opens on `Alphabetically first router`. Deleting a router on the Model Router page detaches it from every profile. Local only.
- `F13.profile-skills`: an OpenHands profile has a **Skills** section listing the server's skill catalog (each labelled `Catalog` or `Your skill`) with a search box; switches save `public_skills`/`disabled_skills`, and a launch loads only the switched-on skills (repository skills always load). Local only.
- `F13.mcp-scope`: **MCP servers** offers **All servers** (every configured server listed, switched on and disabled) or **Choose servers** (a switch per configured server); the choice persists; a chosen server that was removed stays listed with a red warning, and launching with it is refused.
- `F13.secrets-scope`: **Secrets** offers **No profile restriction** (every switch on and disabled) or **Choose secrets**; on an ACP profile, Choose preselects that provider's secret names; the selection persists.
- `F13.acp-form`: choosing **ACP (external subprocess)** shows Preset, Command, Credentials and Model; each preset prefills its command and its model choice (`Agent default`, or Gemini CLI's preferred `gemini-2.5-pro`), **Custom** empties the command and disables Save until one is typed, typing a preset's exact command selects that preset, and the Model list's **Custom** opens a free-text model field.
- `F13.acp-local-presets`: on a local backend the Preset list also offers **Pi** and **OpenCode** (with their own commands and credentials); a profile saved on them stores `acp_server` `pi`/`opencode` with `acp_command` `null`. On Cloud both are hidden (blocked here).
- `F13.acp-model-discovery`: for a built-in preset with its default command the Model list comes from the agent: `Asking <agent> which models it offers…` while the agent-server asks it, then its models with `Agent default (<model>)` first; an agent that wants a login says `Sign in or add credentials above to see the models <agent> offers.`, one that cannot start says `<agent>'s models appear here after your first conversation with it. …`; a picked model is saved as `acp_model` and reopens selected.
- `F13.acp-credentials`: built-in presets show a Credentials section (password fields), an auth banner (signed in / configured), a conflict warning for mutually exclusive Claude credentials, and `Already saved — leave blank to keep` for stored values. Credentials are saved as global secrets.
- `F13.acp-preset-credentials`: the Credentials fields follow the preset: Claude Code `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`; Codex `OPENAI_API_KEY`, `CODEX_AUTH_JSON` (multi-line), `OPENAI_BASE_URL`; Gemini CLI `GOOGLE_APPLICATION_CREDENTIALS_JSON` (multi-line), `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`, `GOOGLE_GENAI_USE_VERTEXAI`, `GEMINI_API_KEY`, `GEMINI_BASE_URL`; Pi `PI_AUTH_JSON` (multi-line), `ANTHROPIC_API_KEY`; OpenCode `OPENCODE_AUTH_CONTENT` (multi-line), `OPENCODE_API_KEY`; **Custom** has no Credentials section. With no host login and no stored credential (Gemini here) no auth banner shows.
- `F13.menu-keyboard`: opening the row's `...` menu focuses Edit; ArrowDown/ArrowUp move focus between the enabled items (wrapping, and skipping the disabled **Set as active** on the active row and the disabled **Delete** on the local `default`), Enter runs the focused item, and Tab, Escape or a click outside close the menu.
- `F13.delete`: Delete asks for confirmation; Cancel keeps the row, Delete removes it. Deleting the active profile selects `default` immediately. On a local backend `default`'s **Delete** is disabled (its title reads `The default profile can't be renamed or deleted.`).
- `F13.phone`: the list, row menu and editor fit a 390 px viewport without horizontal overflow.
- `F13.acp-conversation`: a conversation launched from an active ACP profile runs the external agent. Blocked without an approved provider account.
- `F13.cloud-read-only`: on a Cloud backend, organization members see rows without the `...` menu or **Add agent profile**. Blocked without a Cloud account.

## How to get to it (user POV)

- Sidebar settings gear (`backend-selector-settings-link`): on desktop `/settings` redirects to `/settings/agents`. In the settings navigation, **Agent** (`sidebar-settings-/settings/agents`).
- Direct URL `/settings/agents`; the retired `/settings/agent` redirects there.
- Command menu (`Control+k`/`Meta+k` or `command-menu-trigger`): **Agent settings**.
- Getting-started checklist **Customize your agent** and the composer **+** → **Switch agent profile** → **Manage agent profiles** (both mapped in F09/F05).
- On Home, the composer **+** → **Switch agent profile** list activates a profile like **Set as active** (F05.agent-profile-switch).
- All per-profile actions are in the row's `...` menu (`agent-profile-menu-trigger`). The editor has no route: it replaces the list in place.

## Driving it with control-openhands

Preconditions:

- Baseline state (launched, doctored, `onboard --skip` done) on a **fresh** run. `F13.editor-no-llm` must run before `control-openhands llm preset deepseek`; everything from `F13.stale-llm-ref` on needs the preset (`deepseek-flash` active, `deepseek-pro`).
- A fresh run has one profile, `default`, active, whose LLM profile is `default` (which does not exist). `control-openhands api GET /api/agent-profiles` shows it. On first load the UI migrates the global settings into it once (`misc_settings.app_preferences.default_profile_migrated` `true`; `api GET /api/agent-profiles/default` then carries `public_skills`, `condenser` and `verification`).
- `F13.profile-router` needs two routers: create `QA_router` (classifier `deepseek-flash`, the `F12.create-first` prompt and a two-line table naming `deepseek-flash` and `deepseek-pro`) and `QA_router_2` through Settings → Model Router (F12).
- `F13.mcp-scope` needs two configured MCP servers. Arrange them with `control-openhands api POST /api/settings/mcp/qa_mcp_a --data '{"transport":"stdio","command":"qa-no-such-command","enabled":false}' --write` and the same for `qa_mcp_b`.
- `F13.acp-conversation` needs the provider's agent CLI and an approved account; `F13.cloud-read-only` needs a Cloud organization member login. Both are blocked here.
- Dropdowns are autocompletes. Pick an option with `control-openhands browser choose 'testid=<testid>' '<label>'` (proven on `agent-type-selector`, `agent-preset-selector`, `agent-model-selector` (`Custom`), `agent-profile-llm-selector`, `agent-settings-mcp-mode` and `agent-settings-secrets-mode`). ## Gotchas

- The editor is not a route: `browser url` stays `/settings/agents` and `browser reload` drops unsaved edits back to the list. The settings page header (`settings-page-subtitle`) is hidden while it is open.
- Autocomplete dropdowns: clicking an input that already shows a value can open an empty listbox (the text filters it), and an option click then times out. The toggle-button opener does not always open the list either: on the Edit editor's `agent-profile-llm-selector` (bottom of the form) the option click timed out 5 of 5 times right after opening the editor, and the model list's `Custom` option once detached mid-click after a preset change. `browser choose` avoids the input-filtering problem, but an option may still remain unstable immediately after opening an editor. Reload and reopen before retrying; the suffix-identity check can use the already-selected active LLM without changing that dropdown. A listbox also closes if you spend a command (snapshot, eval) in between, so click the option right after opening.
- A taken name marks the field invalid with an alert reading `An agent profile with this name already exists. …`.
- `has-text=default` matches any row whose LLM profile or name contains `default` (Playwright's text match ignores case); select the seeded profile with `'[data-testid=agent-profile-row]:has([title="default"])'`.
- Model lookups (`F13.acp-model-discovery`) spawn the provider CLI on the agent-server machine through npx with the profile's allowed secrets; they send no prompt. A failed lookup is retried each time the preset is picked again; a successful one is cached for about five minutes per preset and secret set.
- Switch rows are `sr-only` checkboxes inside labels (keyboard reachable): click the label text (`'testid=agent-settings-tool-list >> text=<tool>'`, `'testid=agent-settings-mcp-list >> text=<name>'`) and read `.checked` with `browser eval`. A bare `label` selector segment is parsed as `label=`, not CSS.
- The Active badge, the **Set as active** item and the `Switched to profile` toast all refer to the same active pointer; the LLM page says **Set as default**.
- The OpenHands row's grey text is the LLM profile name, not the kind. A fresh run's `default` shows `default` there although no LLM profile of that name exists until it is edited (`F13.stale-llm-ref`).
- Every local launch sends `agent_profile_id`, `default` included; read `launched_agent_profile` and `agent` on the conversation. A named profile runs its own LLM profile (`launched_agent_profile.llm_profile_ref` `null`); `default`, or a profile whose LLM reference no longer exists, runs the active LLM profile (`llm_profile_ref` is set to it when it differs from the stored reference, otherwise `null`). The Home LLM pill edits the active profile's LLM (`F13.llm-pill-precedence`). `/new` and local child conversations launch through the same path. With no active profile a local launch fails with an error instead of falling back to global settings.
- On a local backend `default` shares state with global pages both ways: switching a server in its MCP list switches it in MCP Servers for every profile, its skill switches are the Skills page's, and picking its LLM activates that LLM profile. Arranged API writes (`llm preset`) do not update `default`'s stored `llm_profile_ref`; the editor preselects the active LLM profile and enables Save (`F13.stale-llm-ref`).
- An unquoted `text=github` click in the Skills list can hit another row containing that text; quote the exact name (`text="github"`) or search first.
- The ACP auth probe runs the provider CLI on the agent-server machine. If that machine has a Claude CLI login, Claude Code can show "already signed in". Use only an explicitly approved account for authenticated ACP checks.
- ACP credentials are global secrets, not profile fields: cancelling the editor saves nothing, but saving any ACP profile with a typed credential writes it to Settings → Secrets (F14) for every conversation.
- **Choose secrets** on an ACP profile also selects provider secret names that are not saved (`CODEX_AUTH_JSON`, `OPENAI_BASE_URL`); they show as switches without descriptions.
- The empty state (`agent-profiles-empty`) and the load-error state (`agent-profiles-load-error`) are not reachable on a local backend: `default` cannot be deleted, and with the agent-server stopped the app swaps to **Manage backends** after a reload, or keeps the cached list without one.
- The refused-launch toast text comes from the Agent Server and changes between versions (`MCP server(s) not configured: <name>` on 1.53.0): assert that one toast names the server and the prompt stays, not the exact wording.
- Opening a row menu focuses its first enabled item. Arrows skip disabled **Set as active**; Escape closes the menu and returns focus to its trigger, while Tab closes it and continues normal tab order.
- The Add agent editor has its own agent description. Parallel tool calls label and description are translated.
- Known issue [#16905](https://github.com/OpenHands/OpenHands/issues/16905): An enabled built-in OpenHands skill can be absent from a new Claude Code ACP session. The enabled/disabled instruction-delivery check needs an approved authenticated Claude Code account, its ACP subprocess and the configured Code Review automation; no provider session is authorized here. (`F13.acp-conversation`).
- Known issue [#16296](https://github.com/OpenHands/OpenHands/issues/16296): Claude Code credential fields remain visible below the already-connected banner, leading users to think keys are required. The connected-state check needs an approved existing Claude CLI login on the agent-server host; a dummy credential does not prove that signed-in state. (`F13.acp-credentials`).
- Known issue [#17051](https://github.com/OpenHands/OpenHands/issues/17051): Codex ACP can work in New Chat while Issue-to-PR automation fails with missing OpenAI API credentials. Reproduction needs an approved Codex subscription login plus a configured Issue-to-PR automation and its repository credentials; the report does not identify the saved automation/profile settings. (`F13.acp-conversation`).
- Known issue [OpenHands/software-agent-sdk#5167](https://github.com/OpenHands/software-agent-sdk/issues/5167): On a headless Docker host an already usable Codex ChatGPT login can still time out during ACP authenticate. Reproduction needs an approved ChatGPT login in the reported headless/read-only-auth-file deployment and its adapter; a desktop or bogus login cannot establish this conditional trigger. (`F13.acp-conversation`).
- Known issue [OpenHands/software-agent-sdk#5995](https://github.com/OpenHands/software-agent-sdk/issues/5995): Claude Code ACP first turns with `claude-opus-5-5` can fail because the pinned adapter bundles an older Claude Code.
