# F15 — Condenser, agent context and verification settings

Settings pages generated from the Agent Server's settings schemas:
**Condenser** (summarize long chats), **Agent Context** (persistent agent
memory) and **Verification** (confirmation mode, security analyzer and the
critic). On a local backend each agent profile owns its condenser and critic:
they are edited in the Condenser and Verification sections of the agent
profile editor (Settings → Agent), `/settings/condenser` opens the Agent page,
and the Verification page keeps only the global Critic API Key, Confirmation
Mode and Security Analyzer under a note that the critic is set per agent
profile. On a Cloud backend the Condenser page and the full Verification page
(with the critic switch and its fields) are global settings pages. Each page
shows the schema's fields in Basic/Advanced/All tiers (only the tiers that have
fields), hides fields whose parent switch is off, and saves through one
**Save Changes** button that stays disabled until a value differs from the
stored one.

The **Runtime** page renders the conversation schema's `runtime` section the
same way: a default runtime (Local, Worktree, Docker) followed by
only that runtime's options.

Source: `src/routes/condenser-settings.tsx`, `src/routes/agent-context-settings.tsx`, `src/routes/verification-settings.tsx`, `src/components/features/settings/sdk-settings/`, `src/utils/sdk-settings-schema.ts`, `src/components/features/settings/agent-profiles/profile-behavior-form.ts`.

## Sub-features

- `F15.condenser-page`: on a local backend `/settings/condenser` replaces itself with `/settings/agents` and no nav item or command leads to it; on a Cloud backend Condenser shows its subtitle, Basic and All tabs (no Advanced), and in Basic only the **Enable Memory Condensation** switch.
- `F15.condenser-all-view`: (Cloud backend) the All tab lists the eight condenser fields with Title Case labels, plain descriptions and their stored values (Max Size `240`, Keep First Events `2`, …).
- `F15.condenser-save`: (Cloud backend) changing Max Size and saving shows **Saving...**, then the saved toast; after a reload the page opens on All with the new value.
- `F15.condenser-dependents`: (Cloud backend) turning condensation off hides the six size/reset fields (Condenser Kind stays); turning it back on un-dirties Save.
- `F15.condenser-kind`: (Cloud backend) Condenser Kind is a dropdown (**LLM Summarizer**, **None**, stored as `llm_summarizing` and `no_op`); the choice persists, and switching back restores the summarizer defaults.
- `F15.save-dirty-state`: on each page Save is disabled on load, enabled after an edit, and disabled again when the edit is reverted by hand.
- `F15.save-errors`: (Cloud backend) a non-integer Max Size is refused in the browser with a toast; a negative one is refused by the server with a 422 toast; nothing is stored.
- `F15.view-scoped-save`: (Cloud backend) saving from a narrower tier keeps the stored values of fields that tier does not show.
- `F15.agent-context-page`: Agent Context shows a single **Persistent Agent Memory** switch with its help text and no tab bar.
- `F15.agent-context-save`: toggling Persistent Agent Memory and saving persists after reload.
- `F15.verification-page`: Verification shows Basic, Advanced and All tabs. On a local backend it starts with the note `Each agent profile turns the critic on or off in Settings → Agent.` and every tier shows only **Critic API Key** (with its OpenHands LLM Key help link) and **Confirmation Mode**; on a Cloud backend every tier shows only **Confirmation Mode** and **Enable Critic** by default.
- `F15.verification-critic-fields`: Confirmation Mode reveals Security Analyzer (Advanced and All). Enable Critic reveals Iterative Refinement (Basic) plus mode, server URL and model (All), and Iterative Refinement reveals threshold and max iterations: locally in an agent profile's Verification section (without the Critic API Key), on a Cloud backend on the page, where Enable Critic also reveals the Critic API Key.
- `F15.confirmation-mode-save`: Confirmation Mode and Security Analyzer (conversation settings) persist after reload, alongside the agent-settings fields on the same page.
- `F15.confirmation-mode-effect`: with Confirmation Mode on and Security Analyzer **None**, a new conversation stops before its first command with **Do you want to continue with this action?** and Cancel/Continue; Continue runs it.
- `F15.runtime-page`: Runtime shows **Default runtime** (`Local` by default, `Worktree`, `Docker`). Local shows nothing else; Worktree adds **Create worktrees from** (`Default branch`, `Current HEAD`, `Another branch, tag or commit`, which reveals its ref field) and **Branch name prefix** (`openhands/`); Docker adds the container memory, CPU and browser fields. The Home launcher starts on the saved default, and saved non-default values reach the next conversation's start request as `worktree_options` and `container`.
- `F15.critic-tuning`: (Cloud backend page; locally the same fields in an agent profile's Verification section) Critic Mode is a dropdown (`Finish and Message`, `All Actions`); the mode, Critic Threshold and Max Refinement Iterations persist after reload, and an out-of-range threshold (`1.5`) is refused with the 422 toast.
- `F15.critic-save`: the Critic API Key persists after reload and comes back masked, and clearing it stores `null`; on a Cloud backend the critic text fields on the page persist too, and clearing them and turning the critic off restores the defaults.
- `F15.agent-context-effect`: with Persistent Agent Memory on, a new conversation's system prompt carries the `.openhands/memory/` instructions; with it off, it does not.
- `F15.tier-after-save`: after a save the tab bar re-derives the tier from the stored values without a reload: saving the last non-Basic field back to its default moves the page to Basic.
- `F15.profile-behavior`: on a local backend the agent profile editor (Settings → Agent, Add or Edit) has Condenser (Basic/All) and Verification (Basic/All) sections rendered from the same schema; they edit that profile's `condenser` and `verification`, never the global settings, offer no Critic API Key, and a new profile starts from the `default` profile's values; reopening a profile always shows its stored values. Known failure (reproduced 2026-10-22, [#18810](https://github.com/OpenHands/OpenHands/issues/18810)): after a reload, Edit intermittently shows the global values instead, and a condenser save from that state overwrites the profile's.
- `F15.unsaved-navigation`: leaving a page with unsaved edits shows no prompt and discards them.
- `F15.command-menu`: the command menu offers **Agent Context**, **Verification settings** and **Runtime** (plus **Condenser settings** on a Cloud backend), and each opens its page.
- `F15.direct-url`: each page renders when opened by URL; locally `/settings/condenser` opens `/settings/agents` instead.
- `F15.phone`: at 390 px the fields stack in one column without horizontal overflow.
- `F15.schema-unavailable`: a backend without the settings-schema endpoints shows `SDK settings schema unavailable.` with an upgrade hint instead of the form (blocked: needs such a backend).

## How to get to it (user POV)

- Sidebar settings gear (`backend-selector-settings-link`, lands on `/settings/agents`), then **Agent Context** or **Verification** in the settings navigation (`sidebar-settings-/settings/agent-context`, `sidebar-settings-/settings/verification`); **Condenser** (`sidebar-settings-/settings/condenser`) is listed only on a Cloud backend.
- Direct URLs `/settings/condenser` (local: opens `/settings/agents`), `/settings/agent-context`, `/settings/verification`, `/settings/runtime`.
- Command menu (`Control+k` or `Meta+k`, or `command-menu-trigger` in the sidebar): **Agent Context**, **Verification settings** and **Runtime** (plus **Condenser settings** on a Cloud backend); locally "memory" finds only Agent Context.
- Per-profile condenser and critic (local): Settings → Agent, **Add agent profile** (`add-agent-profile`) or a row's menu → **Edit**, sections `agent-settings-condenser` and `agent-settings-verification`.
- The effects show up in new conversations only: the confirmation prompt in the chat, and the memory instructions in the conversation's system prompt.

## Gotchas

- Switches are `sr-only` checkboxes (keyboard reachable): toggle by clicking the label text scoped to the page, read `.checked` with `browser eval`.
- `text=Enable Critic` is a case-insensitive substring match and hits the help paragraph `Enable critic evaluation for the agent.` first, so the click does nothing. Quote it: `text="Enable Critic"` (same for `text="Enable Iterative Refinement"`).
- The conversation-owned fields have no `verification.` prefix: `sdk-settings-confirmation_mode`, `sdk-settings-security_analyzer`. Critic fields keep it (`sdk-settings-verification.critic_enabled`).
- Locally the condenser and the critic switch belong to agent profiles: a recipe that opens `/settings/condenser` lands on `/settings/agents`, and `sdk-settings-verification.critic_enabled` is not on the Verification page. Use the agent profile editor's sections (`F15.profile-behavior`), whose tab toggles repeat per section: scope them, `'testid=agent-settings-condenser >> testid=sdk-section-all-toggle'`.
- Saving is tier-scoped: Basic or Advanced saves reset every field the tier hides to its schema default (`F15.view-scoped-save`). Make all edits on All when other non-default values must survive.
- The page opens on the least detailed tier that shows every stored override (any minor override → All). Do not assume Basic after a reload.
- Condenser Kind **None** (`no_op`) still shows the summarizer fields with defaults, although the stored condenser no longer has them, and edits to them are accepted (`Settings saved`) but dropped while **None** is stored. #18049 covers hiding fields that do not apply to the selected kind.
- A server-side validation error (422) is not retried: one `PATCH /api/settings`, `Saving...` for a moment, then the toast `Settings validation failed`, which does not name the field.
- Condenser Kind is served by the Agent Server's settings schema as a user field. Canvas shows its own choice labels and help text rather than raw `llm_summarizing`/`no_op` values or reStructuredText. The dropdown (`F15.condenser-kind`) remains a user setting so additional kinds can be selected. [OpenHands/software-agent-sdk#5495](https://github.com/OpenHands/software-agent-sdk/issues/5495), the schema's developer-facing description, remains an upstream issue.
- Toasts close after a few seconds; read them right after the click, or assert the stored value with `api GET /api/settings`.
- Each instance's agent server keeps its tmux sockets in its own `TMUX_TMPDIR` (see F06 Gotchas), so a confirmed command that returns `The terminal session was reset because the underlying tmux server/session disappeared...` is a finding, not interference from another run; after one, the agent asks to run it again. A confirmed command took up to two minutes to produce its observation. Confirm again and wait with `conversation wait`, not a fixed sleep.
- The confirmation buttons have test ids (`action-confirm-button`, `action-reject-button`) but their accessible names are `Confirm action` / `Reject action`, not the visible `Continue` / `Cancel`: `role=button[name*="Continue"]` finds nothing.
- Basic-tier saves on Verification reset Security Analyzer to `llm` (it is an Advanced field). That is a convenient restore, and a trap if you meant to keep `None`.
- The memory instructions are only visible through the conversation's first event; `conversation events` truncates text, so read `api GET /api/conversations/<id>/events/search?limit=1` and search the JSON.
- A checkout without #18035 shows the condenser minor fields with the schema's English text (`Max tokens`, `Keep first`, raw choice values) and logs 14 `[i18n] Missing translation` warnings on the All tab.
- The dropdowns' clear (×) button has no accessible name and, in this build, clicking it through `role=button >> nth=2` left the value unchanged.
- After every successful save the selected tab is recomputed from the stored values (`F15.tier-after-save`), so a follow-up `fill` on an All-only field can time out because the page silently moved to Basic. Re-click `sdk-section-all-toggle` before each further edit.
- Pressing Enter in a field does not save (no toast, API unchanged, Save stays enabled); only the Save Changes button submits.
- Fields revealed by a parent switch do not exist while the switch is off: `fill` on `critic_threshold` with Iterative Refinement off waits for a missing element.
- Rejecting a pending action (Cancel), the lock chip above the composer and the ⌘↩ / ⇧⌘⌫ shortcuts belong to `F06.confirmation-mode` and `F06.confirmation-shortcuts`; this family only proves that the settings turn the prompt on.
- `browser count 'role=status'` also counts the backend status dot (`backend-status-dot`); use `browser toasts` for toast texts.
