# F29 — ACP agent sessions

A conversation launched from an active ACP agent profile (F13) runs an external
coding agent (Codex, Claude Code, Gemini CLI, Pi, OpenCode) as a subprocess of
the Agent Server. Canvas shows the agent's text as chat messages and each of its
tool calls as a card that updates from running to its result; edits land in the
workspace and show under Changes. The composer's model pill lists the models the
agent reports and switches the running session. Stop pauses the turn, and a
reload or an Agent Server restart should reattach to the same agent session.
F13 owns creating, editing and activating ACP profiles and their credentials;
this family covers what happens once such a conversation runs.

Source: `src/components/conversation-events/chat/` (`event-message.tsx`, `group-events.ts`), `src/components/conversation-events/chat/event-content-helpers/` (`get-acp-tool-call-content.ts`, `get-event-content.tsx`, `should-render-event.ts`), `src/utils/handle-event-for-ui.ts`, `src/components/features/chat/components/chat-input-model.tsx`, `src/hooks/mutation/use-switch-acp-model.ts`, `src/utils/remembered-acp-models.ts`, `src/contexts/conversation-websocket-context.tsx`, `src/hooks/use-agent-state.ts`.

Server: F05, F06, F09.

## Sub-features

- `F29.session-start`: a conversation started from Home with an ACP profile active runs the external agent: `agent_state.acp_agent_name` names its adapter (`@agentclientprotocol/codex-acp`), the composer's model pill shows the profile's model, and the turn ends `finished` with an agent reply.
- `F29.narration-order`: text the agent says before a tool call ("I'm about to run …") shows above that tool call's card, and the text after the last tool call is the turn's final message; no text from one step joins the next.
- `F29.reload-order`: after a reload the transcript keeps the order it had while streaming.
- `F29.tool-cards`: each ACP tool call is one card: a terminal call is titled with its command, an edit is titled `Editing files` and carries the path and new text; the card goes from running (`in_progress`) to its terminal status (`completed`, `failed`).
- `F29.file-changes`: a file the agent creates with its edit tool exists in the workspace and appears under Overview → Changes as `Uncommitted`, `1 file`, with its path.
- `F29.follow-up`: a second message in the same conversation continues the same agent session: the agent answers from the earlier turn's context without running tools.
- `F29.model-switch`: the conversation's model pill (`chat-input-llm-model`) lists the models the agent reports (`chat-input-acp-model-option-<id>`); picking one updates the pill and the conversation's `agent.acp_model`, and the next turn runs on it.
- `F29.live-controls`: while an ACP turn runs, the composer shows the Stop button and the live activity line names the current tool call.
- `F29.stop`: Stop pauses the conversation (`paused`), turns the in-flight tool card `failed`, records an `InterruptEvent`, and stops the running command.
- `F29.restart-resume`: after an Agent Server restart, a follow-up in an ACP conversation resumes the same agent session and keeps its context.
- `F29.usage`: an ACP turn records usage under `stats.usage_to_metrics.acp-managed` with the session's model name and an accumulated cost.

## How to get to it (user POV)

- Settings → Agents: add an ACP profile (preset **Codex**, credentials in its **Credentials** section) and **Set as active** (F13). Every recipe here starts from that active profile.
- Home composer → send a message: starts the ACP conversation (`F29.session-start` and the turn checks).
- An open ACP conversation's composer: send a follow-up, the model pill (`F29.model-switch`), Stop (`F29.live-controls`, `F29.stop`).
- Overview → Changes (`conversation-overview-toggle` → `conversation-overview-diffs`) for `F29.file-changes`.
- Reloading the page, or restarting the backend, for `F29.reload-order` and `F29.restart-resume`.

## Driving it with control-openhands

Preconditions:

- A run with no other ACP profile active, then `control-openhands onboard --skip` and `control-openhands fixture git-repo` (workspace `qa-repo`).
- An approved Codex ChatGPT login on this machine (`~/.codex/auth.json`, `auth_mode` `chatgpt`). Record `shasum -a 256 ~/.codex/auth.json` first (see Gotchas).
- The Codex profile, through the UI: `control-openhands browser goto /settings/agents`, `control-openhands browser click 'testid=add-agent-profile'`, `control-openhands browser choose 'testid=agent-type-selector' 'ACP (external subprocess)'`, `control-openhands browser choose 'testid=agent-preset-selector' 'Codex'`, `control-openhands browser fill 'testid=agent-profile-name-input' QA_codex`, `control-openhands browser fill 'testid=settings-acp-secret-CODEX_AUTH_JSON' --value-file ~/.codex/auth.json`, `control-openhands browser wait 'testid=agent-model-discovering' --state detached --timeout 180000`, `control-openhands browser choose 'testid=agent-model-selector' 'Custom'`, `control-openhands browser fill 'testid=agent-model-input' 'gpt-6-luna/low'` (the cheapest Codex model, low reasoning), `control-openhands browser click 'testid=save-agent-profile-btn'`, `control-openhands browser wait-text 'Profile "QA_codex" created' --timeout 15000`, then its row menu (`'testid=agent-profile-row >> has-text=QA_codex >> testid=agent-profile-menu-trigger'`) → `testid=agent-profile-set-active`. Reopening Edit lists the agent's own models (`6.1 Sol` … `5.6 Luna`) and `testid=settings-acp-auth-configured` (`F13.acp-model-discovery` with a real login).
- Without an approved ChatGPT login, `F29.session-start` (with `model` `deepseek-flash`) and `F29.live-controls` run on Codex against DeepSeek's OpenAI-compatible Responses API instead: write `$OH_VERIFY_RUN/private/home/.codex/config.toml` (the run's own `HOME`) with `model = "deepseek-flash"`, `model_provider = "deepseek"` and a `[model_providers.deepseek]` table (`name = "DeepSeek"`, `base_url = "https://api.deepseek.com/v1"`, `env_key = "OPENAI_API_KEY"`, `wire_api = "responses"`), put the key in a mode-`0600` file under `$OH_VERIFY_RUN/private/`, then create the profile as above but fill `control-openhands browser fill 'testid=settings-acp-secret-OPENAI_API_KEY' --value-file <that file>` and `control-openhands browser fill 'testid=settings-acp-secret-OPENAI_BASE_URL' 'https://api.deepseek.com/v1'` instead of `CODEX_AUTH_JSON`, and the Custom model `deepseek-flash`. Without the `config.toml` the adapter rejects `deepseek-flash` (`Could not set model ... (Invalid params)` in `stack.log`) and the turn fails on `gpt-6.1-sol`. Each reply then starts with Codex's `Warning: Model metadata for deepseek-flash not found` line, and the model list and usage bullets keep needing the ChatGPT login.

- **Narrated turn (`F29.session-start`, `F29.narration-order`, `F29.tool-cards`).** `control-openhands browser goto /`, then `control-openhands conversation start --workspace qa-repo --prompt "Work in this repository. - **Live controls (`F29.live-controls`).** `control-openhands browser viewport desktop`, `control-openhands browser goto /`, `control-openhands conversation start --workspace qa-repo --prompt "Run exactly one terminal command: sleep 60 && echo acp-slept > slept.txt. - **Stop (`F29.stop`).** Right after the previous bullet, while the `sleep 60` call runs (reload first if the Stop button is missing), `control-openhands browser network --clear` and `control-openhands browser click 'testid=stop-button'`: `browser network --filter <id>` shows `POST /api/conversations/<id>/interrupt` `200`, `conversation status <id>` is `paused`, the events end with the `sleep` card turned `failed` and an `InterruptEvent`, and `browser count 'testid=play-button'` is `1`. Expected: the command stops, so after 60 s `test -f "$OH_VERIFY_RUN/workspace/qa-repo/slept.txt"` fails. Known failure (reproduced 2026-11-09 with Codex, [OpenHands/software-agent-sdk#4990](https://github.com/OpenHands/software-agent-sdk/issues/4990)): the `sleep` process keeps running after Stop and writes `slept.txt`. Reply with only the file name. Do not run any tools." --wait --timeout 300`. Expected: `README.md`. The adapter keeps its Codex state in the conversation's durable `CODEX_HOME`, so `stack.log` logs no `ACP load_session(...) failed` and no fresh session starts.

## Gotchas

- Use only an explicitly approved login, one run at a time. `CODEX_AUTH_JSON` copies the ChatGPT login (with its refresh token) into the run, and the Codex adapter refreshed it at every start in the 2026-11-04 runs (`last_refresh` in the run's `openhands-codex-*/auth.json` became the start time). A refresh retires the previous refresh token, so a second run or a restarted one holding the older copy fails with `ACPAuthRequired: ChatGPT authentication did not complete in time`, and so would the host's own Codex CLI at its next refresh. Before `stop`, copy the newest run copy back (`ls -td "$TMPDIR"openhands-codex-* | head -1`, after checking its `account_id` matches) over `~/.codex/auth.json` with mode `0600`, keep a backup of the original, then check `codex exec --skip-git-repo-check -s read-only -m gpt-6-luna "Reply with only: ok" < /dev/null`. Never publish screenshots of the Credentials fields.
- Keep every prompt confined (`stay inside this folder`, `Do not run any tools` where none are needed): the external agent's tools run as your user, outside the Agent Server's own tool layer.
- An ACP conversation's first turn starts the adapter through npx; the first run on a machine can take a minute while npx downloads it.
- Claude Code, Gemini CLI, Pi and OpenCode sessions need their own approved accounts (OpenCode's free models need none); the recipes here are proven with Codex only.
- OpenCode's free models need no account but share a usage limit: once it is reached (as on a shared egress), the run's `private/home/.local/share/opencode/log/opencode.log` logs `Free usage limit reached`, the turn stays `running` on `Thinking` with no tool call and never finishes; pause it with `conversation pause <id>`.
- When the stack runs inside a Claude Code session, the Claude Code preset reports `You're already signed in to Claude Code` from that session's own environment, which the Agent Server passes on. That is not an approved account for these recipes: do not start Claude Code conversations there.
- An ACP conversation without an LLM profile keeps the truncated first message as its title: title generation uses an LLM profile (F16).
