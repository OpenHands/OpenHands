# F31 — Factories

A factory is a named group of automations. The sidebar shows **Factories**
only when the user has turned the feature on and the automation service
supports factories. `/factories` lists the organization's factories with their
automation counts, and `/factories/<id>` shows one factory's automations in the
same dashboard as Automate, limited to that factory. A user who can manage
automations can create a factory, rename or delete it, and move an automation
into or out of a factory from the automation's actions menu. An Enterprise
backend whose license grants worklogs adds a **Worklogs** section to each
factory; other backends do not offer it. A local backend turns the
feature on in Settings → Experimental. Cloud and Enterprise turn it on with the
`enable_factories` web-client flag, which a local run cannot set.

Source: `src/routes/factories-list.tsx`, `src/routes/factory-detail.tsx`, `src/routes/factory-worklogs.tsx`, `src/hooks/query/use-worklogs.ts`, `src/api/cloud/worklog-service.api.ts`, `src/routes/automation-detail.tsx`, `src/hooks/query/use-factories.ts`, `src/hooks/use-factory-context.ts`, `src/constants/factories.ts`, `src/components/features/factories/`, `src/components/features/automations/change-factory-modal.tsx`, `src/components/features/sidebar/sidebar-rail-body.tsx`.

## Sub-features

- `F31.hidden-when-off`: with the `factories` switch off, the sidebar has no Factories entry (`sidebar-factories-link`), and `/factories` shows `This automation service does not support factories.` (`factories-unsupported`).
- `F31.turn-on`: the Factories switch (`experimental-switch-factories`) in Settings → Experimental saves at once, `GET /api/settings/experimental` reports `factories` as enabled, and after `browser reload` the sidebar shows **Factories**.
- `F31.list-empty`: with no factories, `/factories` shows `No factories yet` and `A factory is a group of automations. This organization has none yet.` (`factories-empty`) and a **New factory** button (`factories-new`).
- `F31.create`: **New factory** opens a name dialog (`factory-name-modal`); **Create** (`factory-name-submit`) saves the factory and opens its page at `/factories/<id>`; `GET /api/automation/v1/factories` lists it, and the list shows its row (`factory-row-<id>`) with the name and an automation count of `0`.
- `F31.open`: a factory's row link (`factory-link-<id>`) opens `/factories/<id>`: a navigation panel titled with the factory name, an **Automations** item, **Back to factories** (`factory-back-link`), and `No automations in this factory yet` (`factory-automations-empty`) while it has none. **Back to factories** returns to the list.
- `F31.rename`: **Rename** in the factory page's actions menu (`factory-actions`, the kebab) opens the dialog with the current name filled in; saving a new name changes it in `GET /api/automation/v1/factories` and in the navigation panel title.
- `F31.scoped-dashboard`: a factory's page shows the cards (`automation-card-<id>`) of its own automations only; `/automations` shows every automation, in a factory or not.
- `F31.keep-factories`: an automation opened from a factory has `?factory=<factory id>` in its URL, its **Back** link goes to that factory's page, and **Factories** stays the current sidebar item.
- `F31.change-factory`: **Change factory** in the automation's actions menu opens a dialog (`change-factory-target`, a select with `No factory` and each factory); choosing `No factory` and confirming shows `<name> is no longer in a factory.`, sets `factory_id` to `null` in `GET /api/automation/v1/<id>`, lowers the factory's `automation_count`, and drops `?factory=` from the URL.
- `F31.delete`: **Delete** in the factory page's actions menu opens `Delete factory` with `Delete the factory "<name>"? This can't be undone.`; confirming (`factory-delete-confirm`) removes the factory and opens `/factories`. While the factory still has an automation the service refuses: the dialog closes, an error toast shows the service's reason (`Factory has 1 live automation; remove them from it first`), and the factory stays.
- `F31.worklogs-unavailable`: on a backend whose license does not grant worklogs (every local backend), the factory page has no **Worklogs** item (`factory-navigation-worklogs`), and the direct URL `/factories/<id>/worklogs` shows the factory page with `Worklogs are not available on this deployment.` (`worklogs-unsupported`).
- `F31.not-found`: `/factories/<well-formed id that does not exist>` shows `Factory not found` (`factory-not-found`) and **Back to factories**.
- `F31.turn-off`: turning the switch off again removes the sidebar entry after `browser reload`, and `/factories` shows the unsupported message.

## How to get to it (user POV)

- Sidebar **Factories** (`sidebar-factories-link`), once the feature is on.
- Settings → Experimental → **Factories** to turn it on or off (see F30).
- Direct URL `/factories` or `/factories/<id>`.
- Rows in the factories list.
- A factory page's actions menu → **Rename** or **Delete**.
- Direct URL `/factories/<id>/worklogs` (the Worklogs section).
- An automation's actions menu → **Change factory**.

## Driving it with control-openhands

Preconditions:

- Baseline state. No LLM is needed.
- The Agent Server must list the switch: `control-openhands api GET /api/settings/experimental` has an entry with key `factories`. Agent Server 1.63.1 is the first release that has it; 1.63.0 and older do not. If the entry is missing, relaunch with `control-openhands launch --new --sdk-version 1.63.1`, or record the recipes `blocked`.
- The automation service must support factories: `control-openhands api GET /api/automation/v1/capabilities --pick body.features` includes `factories` (automation 1.34.0 and later do; the recipes run on the pinned automation 1.36.0 with Agent Server 1.64.1).
- The switch starts off. Read it with `control-openhands api GET /api/settings/experimental` (the `factories` entry's `enabled` is `false`).
- Cloud and Enterprise behavior (the `enable_factories` flag, a member without `manage_automations` seeing no New factory, Rename or Change factory) needs a Cloud account or an Enterprise backend and is `blocked` here.

## Gotchas

- The switch is a visually hidden checkbox: click it with `--force` and read its state from the API, as in F30.
- `/factories` shows `This automation service does not support factories.` both when the switch is off and when the automation service lacks factories. The text does not say which.
- Creating a factory opens its page; it does not stay on the list. Go back with **Back to factories** to see the row.
- `factory-navigation-automations` matches twice (the desktop and the phone navigation). Use `factory-navbar-desktop` for the factory name.
- The page says `Factory not found` only when the service answers `404`. A malformed id such as `/factories/does-not-exist` gets status `422` from the service, and the page shows `Failed to load factories` with a **Retry** button. Use a well-formed id for the not-found recipe.
- The change dialog's select is native: use `browser select`, not `click`, to choose an option.
- A fresh run starts with the switch off and no factories. The recipes build on each other in the order written, so run them from the top on one `launch --new`.
- At phone width the factory page shows the **Automations** strip (`factory-navbar-mobile`), **Back to factories** and the actions menu, but not the factory's name: the name heading belongs to the desktop navigation. Only the Rename and Delete dialogs name the factory there.
- Deleting a factory with worklogs also deletes its worklogs on an Enterprise backend that grants them; the dialog then says `Delete the factory "<name>" and its worklogs? This can't be undone.` A local run cannot reach that wording.
- Not mapped yet: **Add Automation** inside a factory (Create and Import carry the factory id), saved drafts started from a factory, the worklog list (Enterprise only), and the member view without `manage_automations`.
