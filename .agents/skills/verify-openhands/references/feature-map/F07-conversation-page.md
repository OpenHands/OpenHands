# F07 — Conversation page, header and management menu

The conversation page (`/conversations/<id>`) shows the chat pane: a header with
the runtime status dot, the editable title, the "..." management menu and the
Git actions, Overview and panel toggles, then the message history and the
composer. From the header a user renames, stops or resumes the runtime, opens
the skills, hooks and agent-tools dialogs, exports or downloads the
conversation, jumps to usage and deletes it.

Source: `src/routes/conversation.tsx`, `src/components/features/conversation/`, `src/components/features/conversation-panel/`, `src/components/features/controls/server-status-context-menu.tsx`, `src/hooks/use-conversation-name-context-menu.ts`, `src/api/agent-server-adapter.ts` (the Hooks dialog's `toHooksResponse`).

## Sub-features

- `F07.open-by-url`: `/conversations/<id>` shows header, history and composer, and remembers the id as the backend's last conversation.
- `F07.missing-redirect`: an unknown id toasts "This conversation does not exist…" and redirects to `/conversations`.
- `F07.history-skeleton`: opening a conversation shows a message skeleton until its history has loaded.
- `F07.panel-route`: at phone width (up to 1024 px) the header panel button opens `/conversations/<id>/panel`, the tabs panel full width with a Back button; wider, that URL redirects to `/conversations/<id>` with the drawer open beside the chat.
- `F07.rename-inline`: double-click the title (or menu Rename), Enter or blur saves with a toast; an empty value reverts.
- `F07.status-menu`: hovering the status dot (or tapping it on touch) opens a menu with the state and Stop Runtime (active) or Start Runtime (paused). A conversation whose runtime is missing and cannot be resumed shows neither, and its dot agrees with the sidebar's archive icon. Known failure (reproduced twice 2026-10-20, [#18715](https://github.com/OpenHands/OpenHands/issues/18715)): with the F04 "Missing runtime" arrangement, the page shows `Sandbox no longer available` but the header dot stays green and `browser text 'testid=server-status-context-menu'` reads `Running` / `Stop Runtime`; clicking Stop Runtime gets a 404 from `/interrupt` and the toasts `Failed to stop conversation` and `Conversation not found`.
- `F07.menu-open`: the "..." menu opens under the title; Escape closes it and returns focus to "...", and so does an outside click (without the focus move).
- `F07.menu-items-by-state`: Show Available Hooks and Stop Conversation appear only while the conversation is active.
- `F07.skills-modal`: Show Available Skills lists the loaded skills with expandable rows and Refresh.
- `F07.hooks-modal`: Show Available Hooks lists the workspace's `.openhands/hooks.json` hooks, then the user's `~/.openhands/hooks.json` hooks (agent-servers with OpenHands/software-agent-sdk#5734), by event (read when it first opens for a conversation after a page load, and on Refresh; a reopen within 5 minutes of the last read shows the cached list), or "No hooks configured for this conversation."
- `F07.skills-modal-project`: a workspace with `.agents/skills/<name>/SKILL.md` adds a "Project skills" section above the public ones; each row expands to its triggers and body. The list is read with the page and on Refresh; opening the dialog within 10 minutes of the last read shows the cached list.
- `F07.agent-tools-modal`: Show Agent Tools & Metadata shows the system message and the tool list.
- `F07.export-transcript`: Export… downloads a Markdown or HTML transcript with optional tool details and timestamps.
- `F07.download-zip`: Download conversation data downloads `conversation_<id>.zip`.
- `F07.display-cost`: Display Usage and Cost opens the right panel on the Usage tab; at phone width it opens the panel page (`/conversations/<id>/panel`) on Usage.
- `F07.stop-confirm`: Stop Conversation asks for confirmation; Confirm Close pauses the conversation and returns to `/conversations`.
- `F07.delete-confirm`: Delete Conversation names the title in a confirmation; Cancel keeps it, Confirm Delete removes it and returns to `/conversations`.
- `F07.branch-from-message`: Branch from here on a message forks the conversation as `<title> (branch)`; on a user message the message is left out and its text goes back into the composer.
- `F07.right-panel-toggle`: the header panel button shows and hides the right tabs panel (closed again after a reload).
- `F07.overview-toggle`: the header (i) button shows and hides the Overview column, which is exclusive with the right panel. At phone width it should reveal the Overview content on click. Known failure (reproduced 2026-10-27, [#16792](https://github.com/OpenHands/OpenHands/issues/16792)): at 390×844 the label changes from Show overview to Hide overview, but neither the Overview panel nor a phone dropdown renders.
- `F07.git-actions-menu`: the header Git actions menu offers Commits, Pull, Push, Create PR and Create New Branch; each pre-fills the composer without sending, and Send becomes enabled so the user can submit or edit the prompt.
- `F07.git-control-bar`: under the composer, a folder workspace shows an inert workspace chip and the branch; with a GitHub `origin` the repo and branch chips link to GitHub and Pull, Push and Pull Request appear; an Azure DevOps `origin` links to `https://dev.azure.com/<org>/<project>/_git/<repo>`, and the chip and the Overview repository row show the decoded name (`Web Apps`, not `Web%20Apps`) while the links stay encoded once. The chip icons are visible in every theme. `browser eval` of the workspace (forked-repo), branch, external-link and Pull/Push/Pull Request icon `svg` computed `color` in `testid=chat-git-control-bar` equals its chip label's (`rgb(31, 31, 31)` in Light+, `rgb(0, 43, 54)` in Solarized Light, white in the default dark theme), at desktop and phone width; the GitHub logo in the repo chip keeps its own visible colour.
- `F07.git-control-bar-send`: the Pull, Push and Pull Request chips send their git prompt to the agent at once.
- `F07.cloud-only`: Share publicly, Connect Repo, `task-<uuid>` start URLs, paused-sandbox resume, archived read-only state and the shared-conversation redirect exist only on a Cloud backend.
- `F07.phone`: at 390 px the header keeps its controls and the info dialogs fit the viewport.

## How to get to it (user POV)

- Sidebar conversation row (`conversation-card`), or the home composer submit, which navigates to the new conversation.
- Direct URL `/conversations/<id>`.
- Direct URL `/conversations/<id>/panel`, or the header panel button, at phone width (up to 1024 px); at desktop width that URL redirects to `/conversations/<id>` with the drawer open.
- Hovering a message in the history: **Branch from here** (local backends only).
- Chips under the composer (git control bar) for conversations in a git workspace (home **Open Workspace**).
- Header controls inside `testid=chat-pane-header`: the status dot (`server-status-menu-trigger`), the title (`conversation-name-title`), the "..." button (`ellipsis-button`, aria "More options"), `conversation-git-actions-toggle`, `conversation-overview-toggle`, `right-panel-toggle`.

## Driving it with control-openhands

Preconditions:

- Baseline state (launched, doctored, `onboard --skip` done) and an active LLM profile (`control-openhands llm preset deepseek`).
- A finished conversation: `control-openhands conversation start --prompt "Reply with the single word: pong" --wait --timeout 240` prints its `<id>`.
- A running conversation for the active-only items: `control-openhands conversation start --prompt "Run the shell command: sleep 90 ; then reply with the word done" --wait --until running --timeout 120` prints `<running-id>`. It finishes after about 90 s, so start it right before `F07.stop-confirm` (after a Stop it stays `paused` until Start Runtime).
- A conversation in a git workspace for the git control bar: `control-openhands fixture git-repo --name qa-f07-repo`, then `control-openhands browser goto /` (`conversation start` left the browser on `<id>`), `control-openhands browser click 'testid=open-workspace-button'`, `control-openhands browser click 'role=dialog >> role=combobox[name="Select a workspace"]'`, `control-openhands browser click 'role=dialog >> role=button[name="+ Add Workspace"]'`, `control-openhands browser click 'testid=folder-browser-sidebar-workspace'`, `control-openhands browser click 'testid=folder-browser-up'` three times (to the run directory), `control-openhands browser click 'testid=folder-browser-entry-workspace'`, `control-openhands browser click 'testid=folder-browser-entry-qa-f07-repo'`, `control-openhands browser click 'testid=folder-browser-use'`, `control-openhands browser click 'testid=workspace-launch-button'`, then `control-openhands conversation start --prompt "Reply with the single word: ok" --stay --wait --timeout 240` prints `<git-id>`.
- An automation setup conversation for the setup-leaving bullet, made right after the finished conversation: `control-openhands browser goto /automations`, `control-openhands browser click 'testid=automations-add-automation'`, `control-openhands browser click 'testid=automations-add-automation-create' --expect-url '/automations/setup'`, `control-openhands conversation start --stay --prompt 'Reply with only the word ok. Do not run any tools.' --wait --timeout 180` (prints `<setup-id>`), then `control-openhands browser goto /`.
- Cloud-only rows (`F07.cloud-only`) are blocked without an OpenHands Cloud account.
- Desktop viewport unless a bullet says otherwise.

## Gotchas

- The stop and delete confirmation buttons carry `cancel-button` and `confirm-button`; role names inside `role=dialog` work too.
- `stop-button`, `show-skills-button`, `show-hooks-button` and `show-agent-tools-button` also exist in the composer, and `ellipsis-button` in sidebar rows: always scope to `testid=chat-pane-header` or `testid=conversation-name-context-menu`.
- Stop Runtime (status menu) and Stop Conversation (menu) both navigate to `/conversations`. On a finished local conversation the agent server keeps `finished`; use a running conversation to see `paused` and Start Runtime.
