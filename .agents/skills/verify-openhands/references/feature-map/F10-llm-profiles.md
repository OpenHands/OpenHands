# F10 — LLM profiles

An LLM profile is a named model configuration: provider and model (or a custom
model and base URL), an API key or a ChatGPT subscription, a provider-connection
link, and every advanced LLM option. Under Settings → LLM a user lists profiles
(grouped by provider connection when any are linked), adds and edits them in an
embedded form whose Save first runs a one-token validation call, renames,
duplicates, deletes and sets one as **Default**, and bulk-adds models from a
provider. The Default profile is the model new conversations run on. Provider
connections themselves are F11.

Source: `src/routes/llm-settings.tsx`, `src/components/features/settings/llm-profiles/`, `src/components/shared/modals/settings/model-selector.tsx`, `src/components/features/settings/llm-settings/openai-subscription-auth-card.tsx`, `src/components/features/settings/sdk-settings/`, `src/api/profiles-service/profiles-service.api.ts`.

## Sub-features

- `F10.list`: the "Available Profiles" list shows each row's name, model, a `Default` badge on the active profile and a `...` menu; reachable from the sidebar, the direct URL and the command menu.
- `F10.list-empty`: with no profiles the list reads `No profiles saved yet. Add a profile to save your LLM configurations.` and both Add buttons stay available.
- `F10.list-states`: a spinner shows while profiles load; a load failure shows `Failed to load profiles`.
- `F10.list-grouped`: once any profile links to a provider connection, rows group under the connection's name, with unlinked rows last under `Not linked`; with no linked rows the list is flat again.
- `F10.broken-link`: a profile whose linked connection disappeared shows a warning `Broken link` badge with a re-link tooltip.
- `F10.actions-menu`: the row menu offers Edit, Rename, Duplicate, Set as default (disabled on the Default row) and Delete; it focuses the first item on open, arrows cycle, and Escape, Tab or an outside click close it.
- `F10.set-default`: Set as default toasts `Switched to profile "<name>"`, moves the badge and persists.
- `F10.duplicate`: Duplicate saves `<name>-copy`, then `<name>-copy-1`, with the same model and stored key.
- `F10.rename`: the Rename modal is prefilled and focused; invalid names disable Rename; an unchanged name or Cancel just closes; Enter submits; success toasts and persists, and the Default badge follows a renamed default.
- `F10.rename-conflict`: renaming onto an existing name is refused with a readable message and the modal stays open.
- `F10.delete`: Delete asks `Are you sure you want to delete the profile "<name>"? This action cannot be undone.` with Cancel focused; Cancel keeps the row, Delete removes it with a toast.
- `F10.delete-default`: deleting the Default profile promotes another remaining profile to Default.
- `F10.create`: Add LLM Profile → provider, model and API key → Save shows `Validating...`, toasts `Profile "<name>" created` and returns to the list; the first profile on an empty list becomes Default.
- `F10.name-autofill`: the Profile Name is auto-filled from the chosen model until the user types a name.
- `F10.name-validation`: a name that breaks the rule (letter or digit first; letters, digits, `.`, `_`, `-`; max 64) or duplicates an existing profile disables Save and marks the field invalid.
- `F10.create-validation`: a Save whose validation call fails toasts the provider error and keeps the editor open with nothing saved.
- `F10.custom-model`: the Advanced tab takes a free-text model and Base URL; an empty model is refused with `Model is required`.
- `F10.model-picker`: the Basic provider and model comboboxes group options as Verified Models and Other Models; changing provider clears the model; the OpenHands provider shows account and key help.
- `F10.edit`: Edit loads the profile (`Editing profile "<name>" - save to apply changes`) with the stored key masked; Save stays disabled until something changes; a changed name renames before saving; the stored key is kept.
- `F10.edit-default-reapply`: saving the Default profile re-applies it to the agent's LLM settings.
- `F10.editor-discard`: Back and Cancel return to the list without saving and without an unsaved-changes prompt.
- `F10.schema-validation`: bad values in schema fields (Temperature over 2, Top P over 1, invalid JSON) are refused with a toast naming the field.
- `F10.connection-link`: with connections present the editor shows a Provider connection selector; linking hides API key and Base URL, skips validation on Save and regroups the row; None restores the key field.
- `F10.add-models`: "Add from provider connections" (or a connection row's Add models) creates one linked or keyless profile per checked model; models that already have a profile are hidden.
- `F10.subscription`: Authentication → ChatGPT subscription swaps the model fields for a subscription model list and a device-login card (code, sign-in link, poll, cancel); switching back restores the API-key model.
- `F10.schema-unavailable`: a backend without the settings-schema endpoints shows `SDK settings schema unavailable.` with an upgrade or session-key hint.
- `F10.cloud-readonly`: Cloud org members without edit rights see the list read-only (no Add buttons, no row menus, no Provider connections section).
- `F10.phone`: list, row menu and editor fit a 390 px viewport without horizontal overflow.
- `F10.default-used`: a conversation started after creating a profile in the UI runs on the Default profile's model.

## How to get to it (user POV)

- Sidebar settings gear (`backend-selector-settings-link`, opens `/settings/agents`), then **LLM** in the settings navigation (`sidebar-settings-/settings/llm`).
- Direct URL `/settings/llm`.
- Command menu (`Control+k` or `Meta+k`, or `command-menu-trigger` in the sidebar): search "LLM", choose **LLM profiles** ("Manage models, providers, and API keys.").
- On the list: **Add LLM Profile** (`add-llm-profile`), **Add from provider connections** (`add-models-from-provider`), each row's `...` (`profile-menu-trigger`), and a provider connection row's `...` → **Add models** (`provider-connection-add-models`).
- The create/edit editor has no URL of its own: it replaces the list in place at `/settings/llm`; **Back** (`back-to-profiles`) and **Cancel** (`cancel-profile-btn`) return to the list.

## Gotchas

- Save always runs a real completion against the provider (except for connection-linked profiles). A bad or missing key fails fast with the provider's message; budget one tiny call per Save.
- The editor reopens on whichever tab (Basic, Advanced, All) was used last. Click `sdk-section-basic-toggle` (or the tab you need) before touching its fields, or the `llm-provider-input` / `llm-custom-model-input` you expect will not exist.
- In Edit, `llm-api-key-input` holds the stored *encrypted* key token (about 140 masked characters), not an empty field. Never run `browser value` on it: it prints the token. Leave it untouched to keep the key.
- Provider and model options render in a portal outside the editor and modals: select `testid=provider-item-<name>` unscoped, not under `testid=provider-connection-modal`. Only verified providers have `provider-item-*` IDs and only Other models have `model-item-*` IDs; use `role=option[name="..."][exact]` for the rest.
- `conversation start` navigates the browser to the new conversation; queued settings commands then time out waiting for `add-llm-profile`.
- The auto-filled Profile Name sticks to the default model's name (`gpt-5.6-sol`) after you change model. Always fill `profile-name-input` explicitly, or you save a DeepSeek profile called `gpt-5.6-sol`.
- Set as default (and deleting the Default) rewrites the agent's active LLM settings (`control-openhands llm show`). Deleting every profile leaves the last applied model and key in agent settings, so `llm show` still reports `api_key_set: true` on an empty list.
- Profiles created by Add models are named from the model (`deepseek-chat`, …), not `QA_*`. Clean them up by name, before the connection: the server refuses to delete a connection while profiles reference it.
- The All tab logs hundreds of `[i18n] Missing translation for key "SCHEMA$LLM$..."` console warnings. `browser errors --app-only` counts them; they are not page errors. The only expected app errors in this family are the 409s from the rename conflict and the refused connection delete.
- At 390 px a long profile name beside the Default badge truncates (`QA_...`). Read names with `browser text` on the row, not from the screenshot.
- Toasts last only a few seconds. A `browser screenshot` taken after a slow command can miss them, so assert with `browser wait-text`.
