# F06 — Agent activity: messages, events and lifecycle

Inside a conversation the user watches the agent work: their own messages appear
at once (optimistically), the agent's replies render as markdown, and session
startup, reasoning, tool calls and successful hooks are grouped into collapsible
activity groups that say what they did ("Ran 2 commands, read a file"), whose
rows show commands, outputs, diffs and task lists. While the agent works, the
last group's header names what it is doing right now. Around the transcript sit
lifecycle controls and states: the starting pill, stop and resume, the
confirmation prompt when confirmation mode is on, the reconnecting notice and
error banner, the no-LLM banner and the skill-installed banner. History
pages in from the server, survives reloads and backend restarts, and any message
can be branched into a new conversation.

Source: `src/components/features/chat/chat-interface.tsx`, `src/components/conversation-events/chat/`, `src/components/features/chat/` (messages, banners, `tool-visualizers/`, `task-tracking/`), `src/components/features/markdown/`, `src/themes/syntax-highlighter-themes.ts`, `src/components/features/images/`, `src/components/features/suggestions/`, `src/components/shared/buttons/conversation-confirmation-buttons.tsx`, `src/components/features/controls/agent-status.tsx`, `src/hooks/use-load-older-events.ts`, `src/hooks/mutation/use-fork-conversation.ts`, `src/hooks/use-streamed-text.ts`, `src/hooks/use-scroll-to-bottom.ts`, `src/utils/split-stable-markdown.ts`.

## Sub-features

- `F06.empty-state-suggestions`: an empty conversation shows "Let's start building!" with four suggestion chips; a chip fills the composer with its prompt (a prompt that grows the composer past its height threshold hides the suggestions until the composer is short again). The tab that created the conversation shows them too, below its `Initialized session` group (whose toggle stays clickable), also after reload; sending the first message hides them.
- `F06.user-and-agent-messages`: user and agent bubbles; a long user message is clipped with a gradient and expands on click ("View More"). Drag-selecting inside a message keeps the selection in the message list, also when the drag runs past the feed's edge. On a reply taller than the viewport (`Reply with a numbered list of 60 short lines, 'line 1' to 'line 60'. Do not run any tools.`), scrolled up from the bottom (`browser eval` setting `document.querySelector("[data-testid=chat-scroll-container]").scrollTop = 700`), `control-openhands browser drag 'testid=agent-message >> nth=0 >> css=p,li >> nth=<an item about 370 px from the top>' --by 0,600 --steps 150` ends with the `getSelection()` focus node on `chat-scroll-container` itself (clamped to its end: the items below the start are selected, not the composer's model pill in `chat-git-control-bar`), and `--by 0,-400` ends it at the feed's start (`focusOffset` `0`; the header's Git actions text in `conversation-git-actions-toggle` is not selected), at desktop and `browser viewport phone`. Read the focus node and its `data-testid` ancestors with `browser eval`. The feed scrolls to its bottom (down) or top (up) while the pointer is past the edge. A drag that stays inside the feed keeps the focus in `markdown-renderer`.
- `F06.message-copy`: hovering a bubble shows Copy to clipboard; it copies the message's markdown source and the label flips to Copied to clipboard for 2 s.
- `F06.code-block-copy`: hovering a fenced code block in an agent reply shows its own Copy button, which copies only the code.
- `F06.timestamps`: hovering a tool title shows the event's local date and time; message bubbles have their own relative label (below).
- `F06.message-timestamp`: hovering a user or agent message, or keyboard-focusing its timestamp, shows a compact relative label beneath it (`message-timestamp`): under the right edge for a user message, the left edge for an agent message, without moving the messages, tool groups or composer. It reads `Just now` under a minute, then `N minutes ago`, `N hours ago`, `N days ago`, and from seven days the short date (e.g. `Nov 2`; outside the current year `Nov 2, 2026`); a browser clock behind the event reads `Just now`. A visible label refreshes by itself across a minute boundary and a hidden one catches up when shown again. The label is a button named with the exact local date and time, which hovering or focusing it shows as a tooltip (`Nov 2, 2026, 1:30 PM`). Sending and failed (`Failed to send`) user messages have no label.
- `F06.pending-messages`: a sent message shows "Sending..." until the server echoes it; a failed send shows Failed to send with Retry and Dismiss; Retry delivers it exactly once.
- `F06.clock-skew-send`: a message sent while the browser clock runs ahead of the server is still confirmed by the server echo: no lingering "Sending..." and no Retry.
- `F06.failed-send-persists`: a failed send keeps its Retry row after the backend returns and after leaving and reopening the conversation from the sidebar; sending the same text again succeeds without clearing it, and Retry then delivers that attempt exactly once.
- `F06.markdown-rendering`: agent replies render markdown: tables inside a horizontal scroller with edge fades, fenced code (highlighted tokens stay inline, so a TOML `[build-system]` header is one line), inline code, and links that are always underlined in the theme's link colour.
- `F06.markdown-alerts`: GitHub-style alerts in a message (`> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`) render as panels with an icon, a bold label, a coloured left border and a faint tint in the alert's theme colour, with the body in the normal text colour; the label is readable (at least 4.5:1) in dark and light themes. Source: `src/components/features/markdown/blockquote.tsx`.
- `F06.streamed-reply`: a streamed agent reply grows as the model sends it: each delivered chunk is smoothed in over at most about 100 ms, each new word fading in, and the finished reply replaces the streaming bubble in full as soon as it arrives, as finished markdown (tables, code blocks) with no per-word spans. While it streams, the transcript stays pinned to the bottom; scrolling up stops the follow without pulling the user back, and returning to the bottom (button or scroll) resumes it. With reduced motion the words appear without the fade.
- `F06.workspace-path-links`: a workspace file path in an agent reply, and the path chip of a file-editor card, open that file in the Files tab.
- `F06.thinking`: model reasoning appears as a collapsed "Thinking" row that opens with one click; it sits inside the step's activity group, also when the step's visible thought text renders as its own message above that group (a task-list card keeps its own Thinking row before the card).
- `F06.event-groups`: session startup, reasoning, consecutive tool calls and successful or blocked hooks collapse into one activity group until the agent writes visible text; a finished group reads as a sentence-style summary with no final period: `a`/`an` for exactly one item (`Ran a command`, `Ran a hook`, `made an edit`, `used a tool`), a number for more (`Ran 2 commands`), categories in order of first appearance joined by a comma with lowercase continuation (`Ran a command, ran a hook`; `Ran 2 commands, made an edit, used a tool`). A group whose only step is one tool (Thinking aside) is titled with that tool's descriptive title instead (see the tool-visualizers row). Expanding lists one titled row per action (plus `Initialized session` and `Thinking` rows when present).
- `F06.tool-visualizers`: expanding a tool row shows a rich body: terminal command and output (non-zero exit badge `exit N`), file-editor path chip and content. A group with one tool is titled with that tool's title (e.g. `Echo the string qa-solo to the terminal`); when the tool is the group's only item, the first click on the group shows its body directly, with no row title; with `Initialized session` or `Thinking` alongside, the tool stays a collapsed row to expand separately. A row the user opened stays open when more tools join the group; the new rows start closed.
- `F06.markdown-file-preview`: when the agent creates a Markdown file, its row stays expanded and ungrouped and shows a rendered, height-limited preview card with the file name and View, which opens the file in the Files tab.
- `F06.task-list`: task-tracker calls render a "Tasks" card with done / todo icons.
- `F06.events-match`: the stream shows one bubble per message event and one row per action, with no duplicates (compare with `conversation events`).
- `F06.load-older-history`: only the newest 50 events load first; the previous 50 are fetched when the user scrolls the transcript to its top (a "Fetching older messages…" row shows until they arrive) and automatically only while the content is too short to scroll, so the first prompt and all actions appear. A conversation whose newest page already overflows the viewport opens at the bottom with no older-page request until the user scrolls up.
- `F06.scroll-to-bottom`: scrolling up shows a scroll-to-bottom button; clicking it returns to the bottom and hides it.
- `F06.live-activity`: while the agent runs, the last activity group's header (with a spinner) names the current action ("Thinking", then the action title), exposes it through a status region, and the composer status reads Running. Reopening a finished conversation never flashes "Thinking" or a spinner while its history replays.
- `F06.status-indicator`: while a new conversation starts, a "Starting" pill shows above the composer.
- `F06.session-activity`: a conversation started from this tab shows its startup inline as the first activity group, whose heading (with a spinner) names the latest reported startup or resume phase (on Local `Connecting to agent`), then reads `Initialized session`; it merges with the first tool group until the agent writes visible text. A startup-only group expands straight into its distinct phase labels (on Local `Agent connection`); a group that also holds tools lists a nested `Initialized session` entry that expands to them. It survives a reload in the same tab and is absent in another tab.
- `F06.stop-resume`: Stop in the composer interrupts the agent, including a running tool call (status Stopped, play button, an Agent error row for the interrupted call); Play resumes it to completion, at every width including 320 to 390 px phones. Below a 360 px actions row (phones) the control is compact: the icon stays and its `Running`/`Stopped` label is kept for screen readers only.
- `F06.reload-mid-run`: reloading while the agent runs reattaches to the live run; it finishes without duplicated events.
- `F06.reconnect`: when the Agent Server goes away from a connected conversation the composer shows `Reconnecting...` while it retries (a conversation that never connected shows `Disconnected`); after the server returns the page reconnects without a reload. An idle conversation stays otherwise quiet (no notice, banner or toast); a running one shows an inline `Reconnecting...` notice after 30 s and `Still reconnecting. Your agent may still be running.` with Retry after 60 s, and a reconnect clears it.
- `F06.error-banner`: an error the user must see (such as a send that the unreachable server refused) shows a banner with the message, an error icon, Copy and Close; Close removes it. Losing the server alone shows no banner (see the reconnect row above).
- `F06.error-events`: a conversation error (ConversationErrorEvent) surfaces as a warning banner and the composer status Error.
- `F06.confirmation-mode`: with confirmation mode on, a lock chip sits above the composer and each action waits for "Do you want to continue with this action?" with Cancel and Continue (hints `⇧⌘⌫` / `⌘↩` on macOS, `Ctrl+⇧+⌫` / `Ctrl+↩` elsewhere, hidden below 640 px); a cancelled action is marked Rejected and counts as resolved in its group.
- `F06.confirmation-shortcuts`: Cmd+Enter or Ctrl+Enter continues and Shift+Cmd+Backspace or Shift+Ctrl+Backspace cancels a pending action.
- `F06.branch-from-here`: hovering a message shows Branch from here; on an agent message it forks inclusively; on a user message it forks without that message and pre-fills its text in the new composer, ready to send. The branch is titled "<title> (branch)" and keeps working.
- `F06.image-attachments`: images sent with a message show as thumbnails in the bubble; expand opens a lightbox that closes with X or Escape.
- `F06.skill-install-banner`: after the agent installs a skill into the workspace, a banner offers "Start new conversation with this skill" (same workspace) and Close.
- `F06.llm-not-configured-banner`: with no usable LLM, a conversation shows "Your LLM isn't set up yet..." with Set up LLM; suggestions are hidden and sending is disabled. Known failure (reproduced 2026-10-27, [#18999](https://github.com/OpenHands/OpenHands/issues/18999)): on a run where no LLM was ever configured, **New thread → No workspace** opens no conversation; `POST /api/conversations` answers 422 `unresolved_profile_references` and the toast reads `LLM profile 'default' not found`.
- `F06.critic-result`: with the critic enabled, agent messages and the finishing action each carry a "Critic: agent success likelihood" block (stars labelled `Score: <N.N>%`, one decimal, with the percentage beside them); Expand details lists the issue categories (Potential Issues, Infrastructure, Likely Follow-up).
- `F06.hook-events`: hook executions render as rows titled `Hook: <HookType>` (plus the tool name when there is one); successful hooks (no badge) and blocked hooks (amber `blocked` badge on the nested row) fold into the adjacent activity group, counted in its heading (`Ran a hook`, `Ran 2 hooks`). A blocked hook with nothing to group with stays a direct disclosure row of its own, and a failed hook that did not block (`failed` badge) always stays on its own row in the stream. Expanding a row shows its command, exit code, stderr, error or blocked reason and output, with the badges, stderr, error and blocked reason readable (at least 4.5:1) in dark and light themes. A conversation whose history ends with a hook event opens without an error toast.
- `F06.corrective-nudge`: when the model answers with neither a message nor a tool call, the SDK's nudge (`Your last response did not include a function call or a message. …`) shows as a muted, italic `role=note` line with an info icon (`corrective-nudge-message`), not as a user bubble (#17864). A blocked Stop hook's feedback message (`[Stop hook feedback] …`) shows as the same note.
- `F06.phone`: at 390 px the transcript fits the viewport; wide tables scroll inside their own container.

## How to get to it (user POV)

- Open any conversation: a sidebar conversation card, or the direct URL `/conversations/<id>`. Leaving one for the home page: the sidebar's **New Chat** link; coming back: its card again.
- Start one from the home composer (**New Chat**, `/`): type and press Send. `control-openhands conversation start` drives exactly this path.
- An empty conversation: the sidebar's create-thread button (`conversation-panel-new-thread-picker`), then **No workspace** (or a workspace).
- Composer status control (right side of the composer): Stop while running, Play while stopped.
- Hover a bubble: Branch from here and Copy to clipboard icons; hover a message for its relative time (hover or focus that label for the exact date); hover a tool title for its timestamp.
- Confirmation mode and the critic are switched on under Settings → Verification (`/settings/verification`; the page itself belongs to the settings families).

## Driving it with control-openhands

Preconditions:

- Baseline state (launched, doctored, `onboard --skip` done) and `control-openhands llm preset deepseek` (deepseek-flash active). Every prompt below is tiny and stays in the conversation's own workspace.
- Conversation ids are printed as `"id"` by `control-openhands conversation start`, or read from `control-openhands browser url` (`/conversations/<id>`). `<id>` below is always the conversation the step just created or opened.
- `F06.llm-not-configured-banner` needs a second, fresh `control-openhands launch --new --build never` with no `llm preset` (export its run dir as `OH_VERIFY_RUN` for those commands, then `control-openhands stop` it).
- `F06.critic-result`: if an authorized OpenHands (`openhands/…`) or compatible OpenHands LLM-proxy profile is available, use it for the critic check, regardless of the profile used for the rest of the pass. The SDK reuses that profile's LLM key when Critic API Key is empty; a separate critic key is not required. For a non-default proxy deployment, use its compatible critic endpoint. Restore the previous profile after the check. Record `blocked` only when no authorized working critic configuration is available, not merely because the main profile uses another provider; its bullet also says how to arrange a locally scored block with a model only. The automatic-fetch half of `F06.load-older-history` (its 16-command conversation) needs a model; the scroll-to-top half is driven without one, on the dummy profile below, with thirty refused user messages. `F06.hook-events` needs a configured hook (none is set in a fresh run); its bullet arranges three in a fixture workspace and needs no model reply, because the last hook blocks the prompt.
- `F06.clock-skew-send` and `F06.failed-send-persists` need no model reply: a conversation that exists is enough (without a key the agent errors at once, and the user rows still land). Without a key, create the family's conversations with a dummy profile (`QA_DUMMY_KEY=qa control-openhands llm set --profile qa-zeta --model openai/gpt-4o --api-key-env QA_DUMMY_KEY --no-validate`) and `control-openhands conversation start --prompt ...` without `--wait`. `F06.corrective-nudge` needs a genuine provider turn with neither text nor a tool call; it is producer-dependent, not unavailable on Local. A confined two-iteration DeepSeek Flash attempt produced the real SDK nudge on 2026-10-17. Bound the attempt; never fabricate a response/event or guarantee an empty turn. Without one, record the missing producer precondition rather than a rendering pass or product failure.
- The harness browser grants clipboard access: `control-openhands browser clipboard` reads what a Copy button wrote and `browser clipboard --write qa-empty` resets it first.
- A terminal call can come back as "The terminal session was reset..." after this run's agent server restarts; the model reruns it, which turns one action into a group of two (see Gotchas).

## Gotchas

- `browser tooltip` moves the mouse to (0,0) before hovering, and the message timestamp ignores the pointer until its message is hovered, so `browser tooltip` on the timestamp times out; hover the message, then the button, then read `role=tooltip`. A tooltip opened by `browser hover` can stay open after the mouse moves away, so read it right after hovering.
- `control-openhands conversation events <id>` returns the last 25 events unless you pass `--last N`; it reads the server's 100-event pages until `N` rows are in hand (`pages` says how many it read, `more: true` that older pages remain), so `--last 500` covers a 150-event conversation in two pages (`total` `152`, `pages` `2`, `more` `false` on the Older history conversation; `--last 25` there reads one page, `more` `true`) and `--from-start` reads from the oldest. `--kinds` and `--grep` filter before `--last` counts, and pages are read until `--last` matching rows are in hand: `--kinds MessageEvent --last 3` is the three newest messages, `--kinds MessageEvent --last 500` all thirty, and `--grep 'qa older 1'` reaches `qa older 1` on the oldest page with the default `--last` (`count` `11`, `pages` `2`). Event texts are cut at about 160 characters.
- `--observe` takes the same selector syntax as the verbs: `testid=` and plain CSS segments (joined with ` >> `) are watched by an in-page MutationObserver (`observedBy` `mutation`; the Older history bullet's `--observe 'testid=loading-older-events'` is one), while other engines (`role=`, `text=`, `nth=`) are polled every 20 ms instead (not driven in this family).
- A summary lists its categories in the order they first appear in the event list (`F06.event-groups`), which can differ between the live stream and history. With `{"pre_tool_use":[{"matcher":"terminal","hooks":[{"type":"command","command":"echo \"Workspace check passed\"","timeout":10}]}]}` as `.openhands/hooks.json` of a `fixture git-repo --name qa-wording` workspace, `control-openhands conversation start --workspace qa-wording --prompt "Run exactly one terminal tool call with the command: printf 'Workspace ready\n'. Do not run any other tools or commands. Then reply with only: The workspace is ready." --wait --timeout 180` shows `Ran a command, ran a hook` live, while reopening the conversation (`browser goto /conversations/<id>`) shows `Ran a hook, ran a command`, because the server's history lists the `HookExecutionEvent` before the `ActionEvent` it ran for.
- `role=button[name="Expand"]` also matches "Expand thinking" and "Expand actions"; use `[exact]` to target tool rows. Each click flips the row to Collapse, so `nth=0` walks to the next collapsed row.
- Tool rows show no success icon; the only indicators are the `exit N` badge for non-zero exits and a clock icon (`status-icon`) for timeouts. The clock uses the theme's warning colour (`fill-feedback-warning`): 6.10:1 on the Light+ chat panel and 6.50:1 on Solarized Light. A follow-up `Call the terminal tool exactly once with command 'sleep 3' and its timeout parameter set to 1 (seconds). Do not run anything else. Then reply DONE.` produces one (`control-openhands browser count 'testid=status-icon'` is `1`). A single action is not grouped: it renders as a bare row without `event-group`.
- The model writes the tool titles and may append to commands (it turned `ls /missing` into `ls ...; echo "EXIT:$?"`, exit 0). Ask for the command "verbatim, with nothing appended" when the exit code matters.
- The agent itself may open files with `canvas_ui_control` (a third action in the echo/file run). Close the file tab before proving that a path link opens it.
- On Settings → Verification the Security Analyzer field (All tab) is shown only while Confirmation Mode is on: switch Confirmation Mode on first, then pick the analyzer. Check `api GET /api/settings` after saving.
- Confirmation mode with the default Security Analyzer `LLM` uses ConfirmRisky(HIGH): harmless commands run without a prompt. Set the analyzer to `None` to confirm every action, and restore `LLM` afterwards. The composer stays editable while waiting (status "User needed"); the buttons read Cancel / Continue.
- The confirm and cancel shortcuts accept Meta or Ctrl and ignore a held key's auto-repeat; once a response is sent the listener is detached, so a second press sends nothing (#18127). Hints read `Ctrl+↩` / `Ctrl+⇧+⌫` off Apple platforms.
- Known failure, Canvas UI ([#18202](https://github.com/OpenHands/OpenHands/issues/18202), reproduced 2026-10-27): after a user-message branch the composer holds the prefilled text but Send stays disabled (`browser enabled 'testid=submit-button'` is `false`, and a click on it times out with `element is not enabled`). The prefill is a saved draft that `src/hooks/chat/use-draft-persistence.ts` writes into the field without an input event, and the composer is reused across the client-side switch, so its Send state keeps the source conversation's empty field. Editing the text, a reload, or Enter in the field (`browser press Enter --selector 'testid=chat-input'`) all work. A draft restored by a sidebar switch behaves the same (F05 Gotchas).
- Known failure, likely Agent Server: every message in a branched conversation ends with `ConversationErrorEvent` `LLMAuthenticationError` ("Your LLM API key appears to be invalid or has expired."), while the source conversation keeps working (OpenHands/software-agent-sdk#5465). Do not use branches as fixtures for other checks.
- The agent server starts each terminal session on its own tmux socket (`openhands-<random hex>`) inside its own `TMUX_TMPDIR`: `launch` sets a per-run `/tmp/ohv-tmux-<hash>`, and a plain `agent-canvas` creates `<state>/tmux` and passes it on, so another instance stopping or restarting does not touch this run's terminals. After this run's own `restart`, a follow-up terminal command ran once with its output and no reset (2026-10-17). If a row still comes back as "The terminal session was reset because the underlying tmux server/session disappeared" (clock `status-icon`), the model usually reruns the command; expect an extra action.
- The `ConversationErrorEvent` banner is not restored after navigating away and back (or a reload); read the error from the events API instead.
- After `restart`, reconnection takes about 20 s without a click; click `error-message-banner-retry` to reconnect at once. The error banner does not come back after a page reload once the stack is healthy.
- "Sending..." lasts about 100 to 650 ms on a local stack, too short to hover and click `chat-message-stop`; that stop path is not driven here. The `F06.pending-messages` failure path needs `service stop agent-server`.
- `browser clock` installs a fake clock that stays with the page across reloads and client-side navigation. Install it before the `goto` whose page should see it, and put the date back with `browser clock --offset-ms 0` plus `browser reload`; compare `browser eval "new Date().toISOString()"` with `date -u` when in doubt. That does not uninstall it: `performance.now()` stays far ahead of `document.timeline.currentTime` (`browser eval "[performance.now()|0, document.timeline.currentTime|0]"`), and framer-motion's opacity animations then never progress (accordion bodies in Commits and Changes stay at `opacity: 0`, empty-state suggestions and tab tooltips never leave, the active drawer tab's label is invisible). End every clock check with `browser stop` and `browser start` (then `browser goto` the page again) before driving anything else; the two readings then match.
- The pending-message queue lives in page memory, so a failed bubble survives sidebar navigation and a backend `restart` but not a `browser reload` or `browser goto` of the conversation (`src/stores/optimistic-user-message-store.ts`). Leave and return through the sidebar when proving `F06.failed-send-persists`. The sidebar card's title is the first message or model-written: click its link by id, `'a[href*="/conversations/<id>"] >> nth=0'`.
- Both the pending bubble and the echoed message carry `testid=user-message`, so `count 'testid=user-message >> has-text=...'` is one too high while a failed bubble is still shown; count attempts with `conversation events <id> --kinds MessageEvent` (user rows: `"source": "user"`) and the bubbles with `chat-message-retry`.
- Local `Stop` calls the Agent Server's interrupt (Cloud pauses the sandbox instead, see `pauseConversation`): a command already running in the terminal is cut off, recorded as `AgentErrorEvent` + `InterruptEvent`, and after Play the model only reports the interruption.
- The no-LLM banner reuses the home banner's test ids (`home-llm-not-configured-banner`). It exists only in a run where no LLM was ever configured: use a separate `launch --new`, never remove the profile from the shared run.
- Read the clipboard with `control-openhands browser clipboard`, never `browser eval "navigator.clipboard.readText()"`. An agent bubble that contains a code block holds two `copy-to-clipboard` buttons (the code block's is hidden until hovered): scope the bubble's with `>> nth=0`.
