# F14 — Secrets

Secrets are named values the agent can use during conversations. A user lists,
adds, edits and deletes them under Settings → Secrets; saved values are never
shown again, and every new conversation receives them as environment variables.

Source: `src/routes/secrets-settings.tsx`, `src/components/features/settings/secrets-settings/`, `src/api/secrets-service.ts`, `src/components/features/conversation/secret-request-card.tsx`, `src/services/secret-request.ts`, `src/stores/secret-request-store.ts`, `src/constants/secret-request.ts`, `src/api/request-secret-client-tool.ts`.

## Sub-features

- `F14.list`: the Secrets page lists each secret's name and description with Edit and Delete actions; the launcher-seeded `OPENHANDS_AUTOMATION_API_KEY` is always present.
- `F14.create`: adding a secret persists it; it is listed after a reload.
- `F14.create-validation`: duplicate names, names that break `^[a-zA-Z][a-zA-Z0-9_]{0,63}$` and empty values are refused with a message.
- `F14.edit`: editing the description with the value left blank keeps the stored value; Save stays disabled until something changes.
- `F14.delete`: deleting asks for confirmation; Cancel keeps the row, Confirm removes it for good.
- `F14.agent-access`: a conversation started after the secret was saved sees it as an environment variable.
- `F14.phone`: the page and its forms fit a 390 px viewport without horizontal overflow.
- `F14.form-back`: the Add and Edit forms replace the list with an **Add a Secret** / **Edit a Secret** title and a **Back** button; Back (like Cancel) returns to the list and discards the draft.
- `F14.rename`: the Edit form's name is editable; renaming with the value left blank keeps the stored value under the new name, and renaming onto an existing name is refused with `Secret already exists`.
- `F14.edit-value`: typing a value in the Edit form (labelled "Secret Value (leave blank to preserve the existing value)") replaces the stored value for new conversations.
- `F14.delete-escape`: Escape closes the delete confirmation without deleting.
- `F14.value-reveal`: the value field in the Add and Edit forms and in the request card is a masked password input. Its eye button (**Show secret**, then **Hide secret**) shows and hides only what was typed, never a stored value; it does not submit or save, and the field is masked again when the form reopens or another secret is edited.
- `F14.agent-request`: in a local conversation the agent's `request_secret` tool adds a **The agent needs a secret** card in the chat, right after the tool call, with its reason and the name prefilled; it does not block the conversation, so the agent can keep working and the user answers when ready. Add secret saves it, attaches it to the running conversation and reports `saved` to the agent, Cancel reports `not_saved`, and a name that is already saved is attached without a card. The value never reaches the agent's events.

## How to get to it (user POV)

- Sidebar settings gear (`backend-selector-settings-link`), then **Secrets** in the settings navigation (`sidebar-settings-/settings/secrets`).
- Direct URL `/settings/secrets`.
- Command menu (`Control+k` or `Meta+k`, or `command-menu-trigger` in the sidebar): search "Secrets", choose **Secrets settings**.
- The agent itself, in a conversation: its `request_secret` client tool adds the request card (`testid=secret-request-card`) to the chat on `/conversations/<id>` (`F14.agent-request`).

## Gotchas

- Settings nav test ids embed the route, slashes included: `sidebar-settings-/settings/secrets`. Quote the selector as written.

- The value field is a password input (`type=password`, `autocomplete=new-password`) with a Show secret / Hide secret button beside it. A revealed value shows in screenshots, and `browser value` masks the field (read its `type` with `browser eval`). Use dummy values only, and never ask the agent to print a real secret. Enter in the value field submits the form.
- Edit forms intentionally show an empty value; that is not data loss.
- The invalid-name check is native browser validation. It shows a tooltip that screenshots do not capture, and it leaves any earlier `Secret already exists` paragraph on screen. Assert with `validationMessage` and the API, not the paragraph.
- The model is the weak link in the agent checks, not the product: asked to print a secret's length or last characters, deepseek-flash replies "I can't run that one" and runs nothing, and even for the equality check it may refuse to repeat `True` in its reply. Use the equality prompt and read the terminal `ObservationEvent`; `conversation events` truncates message text to about 160 characters.
- The conversation Overview has no Secrets entry point: its "..." menu (`conversation-overview-ellipsis`) offers Workspace and Git sections only.
- There is no empty state to reach safely: `secrets-empty` renders only with zero secrets, which means deleting the launcher-seeded key (see below).
- Secrets saved in Settings reach only conversations started after the save. Reuse an older conversation and the variable is missing. Only `request_secret` (`F14.agent-request`) attaches a secret to a running conversation, and only on a local backend.
- `request_secret` is registered on every new OpenHands-agent conversation this frontend launches (not on ACP agents or older conversations) and appears in Show Agent Tools & Metadata (see `F07.agent-tools-modal`). The agent learns the outcome from a hidden `[secret-request] ...` user message; read it with `conversation events <id> --kinds MessageEvent`, not from the chat.
- At 390 px the name column truncates long names (`OPEN…`); use `browser text` on the row rather than the screenshot to read a name.
- `OPENHANDS_AUTOMATION_API_KEY` is seeded by the launcher for automations; deleting it breaks F18/F19 runs in the same stack.
- Known issue [#17710](https://github.com/OpenHands/OpenHands/issues/17710): On the Cloud backend, deleting a secret reportedly adds a suffixed duplicate and leaves the original. Reproduction needs a disposable writable OpenHands Cloud account at the affected service; Local secret CRUD exercises a different transport. (`F14.delete`, `F14.edit`).
