# F22 — Creating automations: templates, setup and import

A user adds an automation in three ways. The **Templates** sub-page
(`/automations/templates`) lists the prebuilt catalog from
`@openhands/extensions` (6 featured, 17 Beta) with search and integration and
trigger filter chips; picking a card either opens a manifest-driven setup dialog at `/automations/new/<id>`
(prerequisites → form → review → **Confirm and create**), or first asks where a
GitHub/Slack responder should run (on OpenHands Cloud, whether to use the
built-in integration instead), or first asks the user to install missing
MCP integrations, or seeds a conversation with the entry's launch prompt.
**Add Automation → Create Automation** opens the agent-assisted setup page at
`/automations/setup`, where the form opens before a conversation exists. Saving a server-backed
draft and testing its generated custom script need no LLM; sending a prompt
starts genuine model assistance through `automation_form_update`. The setup page's own fields,
draft validation, Test and Create each have their own IDs in F28. **Add Automation → Import automation** reads
an exported JSON file, previews it and creates it disabled.

Source: `src/routes/automation-templates.tsx`, `src/routes/automation-setup-route.tsx`, `src/routes/automation-setup-new.tsx`, `src/components/features/automations/` (`recommended-automations-launcher.tsx`, `recommended-automations-section.tsx`, `template-filter-chips.tsx`, `built-in-integration-choice-modal.tsx`, `responder-deployment-modal.tsx`, `create-instructions.tsx`, `import-automation-modal.tsx`, `agent-profile-selector.tsx`, `setup/`), `src/components/features/conversation/conversation-main/conversation-main.tsx`, `src/components/features/manifest/`, `src/manifests/`, `src/hooks/use-start-automation-setup.ts`, `src/hooks/use-launch-skill-in-chat.ts`, `src/hooks/use-responder-url-secret.ts`, `src/utils/automation-export.ts`, `src/utils/automation-catalog.ts`, `src/api/automation-service/automation-service.api.ts`, `src/api/automation-form-client-tool.ts`, `src/api/automation-form-session.ts`, `src/services/automation-form.ts`, `src/constants/automation-form.ts`, `node_modules/@openhands/extensions/automations/`.

## Sub-features

- `F22.templates-page`: `/automations/templates` shows the h1 **Templates**, a description, a search box, the **Filter templates** chips, **Start from a proven workflow** with a count badge (6) and a **Beta** section (17).
- `F22.template-card`: each card shows an icon or logo stack, name, category, two-line description, one trigger-kind badge per way it runs (a clock for **Cron**, a bolt for **Event driven**, named in a tooltip), a plus badge and integration pills (`N MCPs to connect before launch`; `Needs external setup` only for an integration with no installable MCP or native connection, which no current catalog entry has; `Connected` once installed, which needs a working integration and was not reached here); a `+N` overflow button opens a popover without launching the card.
- `F22.templates-search`: the search box narrows cards by name, category, description, launch prompt and integration names; a query (or filter) that matches nothing shows `No matching templates found — check back again soon.` with **Clear filters**, which empties the search and resets the chips.
- `F22.template-filters`: the **Filter templates** chips above the grid are **All**, one chip per integration the offered templates use (their declared integrations plus the provider of a repository picker in their setup form) and **Cron** / **Event driven**. One integration and one trigger kind can be active at once and combine; clicking an active chip clears it and **All** clears both. The chips are pills on one horizontal rail with an edge fade on each side that shows only while chips are off screen there; the rail scrolls with a trackpad or touch, a mouse drag (which never toggles the chip it starts on) or a vertical wheel turn (until the rail reaches its end, then the page scrolls).
- `F22.template-launch-setup`: a card whose entry ships a setup form (custom-automation, news-digest, github-pr-reviewer, qa-changes, …) navigates to `/automations/new/<id>`.
- `F22.template-launch-conversation`: a card without a setup form and with no installable integration missing creates a conversation and pre-fills its composer with the entry's launch command (for example `/ticket-to-code-change:setup`); nothing is sent until the user presses send.
- `F22.template-mcp-install-queue`: a card with missing required integrations opens each one's install dialog in turn; Cancel abandons the launch without creating anything.
- `F22.responder-deployment-choice`: on a local backend a GitHub/Slack-only responder card first asks **Choose how your responder should run**; **Continue with local setup** creates the `OPENHANDS_URL` secret and continues, **Open OpenHands Cloud integrations** opens Cloud in a new tab, X and Escape cancel.
- `F22.built-in-integration-choice`: on an OpenHands Cloud backend whose built-in integration covers a template (GitHub issue to PR, GitLab issue to MR, the Jira issue-to-PR templates, Slack channel monitor), the card first opens **Choose your setup** with two full-width tabs, **Native Integration** (selected first, with a **Recommended** badge) and **MCP Server**, showing one option at a time. The Native Integration tab is a card titled with the integration's name and described as `The fastest and simplest way to set up a <name> responder.` When the user has connected it, the dialog's subtitle reads `You can use OpenHands in <name> today — here's an example:`, the card shows `@openhands Please complete this task!` and its button is **Close**; otherwise it lists three built-in benefits and offers **Connect to <name>**. The MCP Server tab is **Setup Polling Automation** with **Continue with polling setup** in both states. On a narrow screen the tabs stack. A disabled integration, and every local backend, skips the dialog.
- `F22.responder-local-launch`: with the responder's integration already installed (Slack for **Slack standup digest**), **Continue with local setup** skips the install dialog and opens a new conversation whose composer is pre-filled with the entry's setup command (`/standup-digest:setup`). Nothing is sent until the user presses send; Send delivers it as the user message.
- `F22.setup-prerequisites`: **Before you start** lists the entry's integrations with the reason each is needed and **Manage integrations** (`/mcp`); Continue is disabled while a required integration is missing; an entry with nothing to check skips the step.
- `F22.setup-action-kind`: the **Action** combobox (custom-automation: Prompt / Plugin / Upload tarball) swaps the action fields and keeps shared values.
- `F22.setup-form-validation`: Continue checks fields locally (`This field is required.`, `Must be at least N characters.`, `Must be at most N.`) and a field blur sends the draft to the service, whose errors appear under the field (`Value error, Invalid cron expression: …`).
- `F22.setup-agent-profile`: the **Agent profile** combobox appears only for actions that create through `/v1` (Upload tarball and bundle entries), not for Prompt or Plugin; it lists `Default` and every saved agent profile and shows `Default` while no profile is chosen (also after a switch through Prompt or Plugin and after picking `Default`, #18111), picking a profile hides the **LLM profile** field, switching to Prompt or Plugin clears the choice, Review leaves out the hidden LLM profile, and the automation is created with that `agent_profile_id`.
- `F22.setup-plugin-create`: the **Plugin** action takes plugin sources and a prompt, and a picked **Timezone** carries through Review into the created automation (`preset_metadata.plugins`, `trigger.timezone`).
- `F22.setup-tarball-create`: the **Upload tarball** action requires a `.tar`/`.tar.gz` file, shows its file name in Review and creates an automation with the uploaded tarball and the entrypoint. The native file chooser button follows the color theme (its interactive-hover background with contrast text).
- `F22.setup-repository-list`: a repository list field has **Add** (disabled while the input is empty) and a **Remove** per row; an empty required list is refused.
- `F22.setup-review-confirm`: **Review** lists the chosen Action and every setup field the form showed, in the form's order (`Not set` for blanks; the Agent profile choice and a field the form hid, such as LLM profile after an agent profile was chosen, are not listed); **Back** keeps the values; **Confirm and create** creates the automation (enabled) and replaces the URL with its detail page.
- `F22.setup-bundle-create`: a bundle entry (Daily news digest) uploads its script tarball and creates an automation with the bundle's entrypoint, without any account.
- `F22.setup-unsupported`: an entry this deployment cannot run (qa-changes needs event triggers) shows **Not available**, the unmet requirements, **Close** and **Set up in a conversation**.
- `F22.setup-fallback-conversation`: **Set up in a conversation** creates a conversation seeded with the entry's setup message.
- `F22.setup-close`: X or Escape goes back in history; on a cold deep link it replaces the location with `/automations`.
- `F22.setup-unknown-id`: `/automations/new/<id>` for an id no catalog entry claims is a 404.
- `F22.agent-assisted-setup`: **Add Automation → Create Automation** opens `/automations/setup`, whose setup panel collects name, action, trigger, model (LLM profile) and custom code, can ask the agent for help, saves server-backed drafts, opens test runs behind a Back button and dispatches the finished automation. A Prompt or Plugin draft offers no agent profile (their `/v1/preset/prompt` and `/v1/preset/plugin` endpoints take none), so Save draft sends no `agent_profile_id` and succeeds even when other agent profiles are saved.
- `F22.import-picker`: **Add Automation → Import automation** opens a dialog that explains the format (docs link), says the import is disabled, and offers a dropzone and **Choose file**.
- `F22.import-validation`: a file that is not JSON shows the toast `The selected file is not valid JSON.`; a JSON file that breaks the format shows one toast listing every issue; the dialog stays on the picker.
- `F22.import-preview`: a valid file switches the dialog to a preview (Name, Trigger, Prompt, Plugins) with the disabled notice, **Cancel** and **Import automation**.
- `F22.import-confirm`: **Import automation** reads `Importing...` while pending, closes the dialog, shows `Imported "<name>" as disabled. View automation`, and the automation is listed disabled; the toast link opens its detail page.
- `F22.import-choose-file`: **Choose file**, and a click anywhere on the dropzone, open the browser's file chooser; the chosen file is previewed.
- `F22.import-dropzone`: dragging a file over the dropzone highlights it (`data-active="true"`); dropping a `.json` file previews it like **Choose file**.
- `F22.phone`: the Templates grid, the setup dialog and the import dialog fit a 390 px viewport without horizontal overflow; the filter chips stay on one row that scrolls inside the page.

## How to get to it (user POV)

- Sidebar **Automate** (`sidebar-automations-link`), then **Templates** in the Automate sub-page nav (`automations-navbar-desktop >> automations-navigation-templates`; at phone width `automations-navbar-mobile`). The command menu has no Templates entry (searching `template` gives **No commands found**).
- Direct URLs `/automations/templates` and `/automations/new/<catalog-id>` (for example `/automations/new/custom-automation`, `/automations/new/news-digest`, `/automations/new/qa-changes`). A deep link opens the setup dialog over the page; it bypasses the responder and install-queue dialogs that a card click shows first.
- Template cards elsewhere use the same launcher: the **Recommended automations** rail on home/New Chat (F03) and on the empty dashboard (F21.empty-rail), and the onboarding say-hello step (F01).
- Dashboard header **Add Automation** (`automations-add-automation`) → **Create Automation** (`automations-add-automation-create`) or **Import automation** (`automations-import-automation`). The empty dashboard also shows the Create Automation instructions inline (`automations-empty >> automations-create-automation`).
