## 🎯 目标 / Problem (what the issue asked for)

Closes #17893

When the agent finishes, errors, or needs input while Canvas is not focused, the user currently gets no signal unless they happen to be watching the tab. The only existing channel is the `enable_sound_notifications` toggle and `src/hooks/use-agent-notification.ts`, which plays `notification.mp3` — browsers throttle or block audio in background tabs, so the exact situation where you need it is where it doesn't fire.

## 🧪 实现 / Solution (what I did)

### 核心改动

| 文件 | 改动 |
|---|---|

| `src/i18n/translation.json` | 3 个新键（16 语言）：`SETTINGS$OS_NOTIFICATIONS`、`SETTINGS$OS_NOTIFICATIONS_DENIED`、`SETTINGS$OS_NOTIFICATIONS_UNSUPPORTED`。 |

### 关键设计决策

- **无 Service Worker / PWA / Electron 改动**。只用纯 Web API（`new Notification(...)` + Badge API）；service-worker 路径和安装 badge 另见 #17890、#17892。
- **无后端 wire contract 变更**。设置字段已通过 `APP_PREFERENCE_FIELDS` 自动路由到本地 agent-server 的 `misc_settings.app_preferences` 和云的顶层扁平字段。
- **权限只在显式用户动作中请求**。`Notification.requestPermission()` 仅在用户打开开关保存时调用，页面加载、路由切换、conversation 启动时都不 prompt。`denied` 状态在 UI 中解释如何重新启用。
- **稳定 per-conversation tag**：`openhands-attention-${conversationId}` 保证同一 conversation 的重复 attention 转换替换已有通知，不堆积。
- **多 conversation badge 是 follow-up**：当前 badge 只追踪活动 conversation。多 conversation 聚合需要 hook 消费 `conversation-state-store.executionStatusByConversation`。这个 issue 验收标准里的完整多 conversation 行为放到 follow-up PR。
- **`ERROR` 新增到 attention 状态**：原来的三个状态是 `AWAITING_USER_INPUT` / `FINISHED` / `AWAITING_USER_CONFIRMATION`；`ERROR` 作为未计划的终止也应通知。

## 📋 未覆盖的 AC（Follow-up）

- **点击通知聚焦窗口 + 导航**：`notification.onclick` 已经调用 `window.focus()`，但从通知中解析 conversation 并导航到它（React Router）需要 router hook，放到 follow-up。
