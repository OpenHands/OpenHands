# ISO 27001 plugin — scope and limits

This plugin is a **heuristic checker**. It does **not** certify ISO/IEC 27001
compliance, an ISMS, or a Statement of Applicability.

## What it looks for

| Rule | Intent |
|------|--------|
| `ISO-SECRET-AWS` | `AKIA…` access-key pattern |
| `ISO-SECRET-KEY` | `api_key` / `secret_key` / `access_token` assignments |
| `ISO-SECRET-PRIVATE-KEY` | PEM private-key header |
| `ISO-ENV-COMMITTED` | `.env` / `.env.local` / `.env.production` present in the tree |
| `ISO-UNPINNED-DEP` | Unpinned `requirements.txt` or `package.json` (`^`, `~`, `*`, `latest`) |
| `ISO-HTTP-INSECURE` | `http://` URLs that are not localhost/example |
| `ISO-TLS-DISABLED` | `verify=False`, `CERT_NONE`, and similar |

## False positives

- Placeholder tokens in docs (`api_key = "YOUR_KEY_HERE"` if long enough).
- Local HTTP URLs that are not obviously loopback.
- A `.env` file that is gitignored — this plugin does not read git index.

## What this does NOT guarantee

- Annex A control coverage, risk treatment, or audit evidence.
- Secret scanning of git history or cloud parameter stores.
- That a product is “ISO 27001 certified.” Treat hits as review prompts only.
